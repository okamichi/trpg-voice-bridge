# Discordでの利用方法

TRPG Voice Bridgeは、生成した音声を参加者のPlayer（`/player/`）で再生します。Discordなどのボイスチャットを一緒に使っていると、Playerの音をマイクが拾い、環境によってはエコーになることがあります。

その場合は、Playerの音声を止めるか音量を下げるか、ここで説明するDiscord Botで音声を流してください。

Discord Botを使うと、Playerをインターネットに公開しなくても卓を進められます。音声担当者がPlayerで声を設定するほか、VTTのチャットから参加者がDiscordで声を試作・登録する追加機能も利用できます。

## Discord側の準備

### 手順

1. **サーバーを用意する**
   - 既存のサーバーを使う場合、この手順は要りません。
   - Discordで「サーバーを追加」→「オリジナルの作成」を選び、サーバーを作ります。
     - 新しく作ったサーバーには、最初からボイスチャンネルがあります。
     - サーバーの持ち主には、Botを招待する権限（サーバー管理）があります。
2. **Botを作る**（[Discord Developer Portal](https://discord.com/developers/applications)）
   1. 「New Application」を押し、名前を付けて作成します。名前とアイコンは後から変えられます。
   2. 左のメニューの「Bot」で「Reset Token」を押し、表示されたトークンをコピーします。
      - トークンは一度しか表示されません。なくしたら、もう一度「Reset Token」で作り直してください。
      - パスワードや2段階認証の確認を求められることがあります。
      - 「General Information」の「Public Key」はトークンではありません。
3. **Botを招待する**
   - 「General Information」の「Application ID」を、次のURLの `<Application ID>` に入れて開きます。
     ```
     https://discord.com/oauth2/authorize?client_id=<Application ID>&scope=bot&permissions=3247104
     ```
   - 開いた画面で対象のサーバーを選び、「認証」を押します。
   - 管理画面でBotにログインしたあとなら、「招待URLをコピー」でも同じURLを取得できます。

### Botの設定と権限

| 場所                                        | 設定                                                               | 説明                                                                                                                                                  |
| ------------------------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **招待URL**（`permissions=3247104`）        | チャンネル閲覧・接続・発言・メッセージ送信・ファイル添付・履歴閲覧 | ボイス読み上げと、専用テキストチャンネルでの声づくりに使用する                                                                                        |
| 「Bot」画面の権限の一覧（Bot Permissions）  | 触らない                                                           | 招待URLを作るための計算機で、ここで選んでも権限は付かない                                                                                             |
| 「Bot」画面の「Privileged Gateway Intents」 | すべてオフ（初期値）                                               | このBotは使わない（使うのは `Guilds` と `GuildVoiceStates` だけ）                                                                                     |
| 「Bot」画面の「Requires OAuth2 Code Grant」 | オフ（初期値）                                                     | オンにすると、上の招待URLでは招待できなくなる                                                                                                         |
| 「Bot」画面の「Public Bot」                 | オフを推奨                                                         | ほかの人がこのBotを自分のサーバーに追加できないようにする。オフにするときにエラーが出たら、「Installation」の「Install Link」を「None」にしてから試す |
| 「Installation」の初期設定                  | 触らない                                                           | Discordが用意する招待リンク用の設定。自分で作った招待URLを使うので関係ない                                                                            |

- **「管理者（Administrator）」は付けないでください。** トークンが漏れたときに、サーバー全体を操作されてしまいます。
- ボイス読み上げだけなら、メッセージ送信・ファイル添付・履歴閲覧は不要です。Discordでの声づくりを使う場合だけ、専用テキストチャンネルで許可してください。通常のテキストチャット本文を収集する機能はありません。
- **特定の人しか入れないボイスチャンネル**では、Bot用のロールにも、そのチャンネルの「チャンネルを見る」「接続」「発言」を許可してください。許可されていないチャンネルは、管理画面で選べません。誰でも入れる普通のボイスチャンネルなら、何もしなくてかまいません。

### トークンの扱い

- トークンを知っている人は、Botを自由に操作できます。人に見せないでください。
- トークンは管理画面から入力します。Bridgeの保存先の `discord.json`（権限0600）にだけ保存され、管理画面にも表示されません。

## TRPG Voice Bridge側の準備

ソースから `npm start` で起動する場合は、先に `tts-bridge/` でDiscord用の依存を入れてください。ダウンロードしたアプリでは要りません。

```sh
npm --prefix discord ci
```

1. Bridgeを起動し、管理画面を開きます。
2. 「2 Discord Bot」を開き、「Discord Botに接続する」をオンにします。
3. 「Botトークン」にトークンを入力し、「保存してログイン」を押します。ログインするとBotの名前が表示されます。
4. 「ボイスチャンネル」で接続先を選び、「接続」を押します。権限のないチャンネルは選べません。チャンネルの一覧は5秒ごとに更新されます。
5. 「接続状態」のDiscord Botが「接続済み」になれば完了です。
6. Collectorを接続し、Playerでキャラの声を設定して、管理画面の「読み上げ開始」を押します。

- 「Discord Botに接続する」をオフにすると、Botを止めます。手順の見出しを閉じても、接続は続きます。
- 「トークンを削除」を押すと、トークンを消してBotをログアウトします。
- Discordで聞く参加者は、Playerの音声を有効にしないでください。すでに再生中なら「音声を停止」を押してください。ログと声の設定はPlayerで使えます。

### VTTチャットからDiscordで声をデザインする

この追加機能は初期状態では無効です。無効時はこれまでどおり、`（ブリッジ声登録）声の説明` で即時登録します。Player・Chatterの声設定やDiscordのボイス読み上げも引き続き使えます。

1. Discordに `#ブリッジ声登録` などの通常のテキストチャンネルを用意します。Botにチャンネルの閲覧、送信、ファイル添付、履歴閲覧を許可します。
2. Botをログインさせます。Developer Portalの **Interactions Endpoint URLは空欄**にしてください。Gateway経由で操作を受け取ります。特権Intent、Bridgeの公開、ポート開放は不要です。
3. 管理画面の「VTTチャットからDiscordで声をデザイン」で専用テキストチャンネルを選び、「登録コマンドで試聴フォームを開く」をオンにして保存します。
4. 既存の「チャットでの声登録・削除」も有効にし、Collectorを接続します。試聴フォームの利用だけならVC接続は不要です。
5. 参加者がVTTでキャラクターとして `（ブリッジ声登録）イケオジボイス。` と公開発言します。
6. 専用チャンネルのメッセージで試聴します。「基本設定」で声の名前・説明・速度・試聴セリフ、「詳細設定」でseed・steps・CFGを編集できます。「既存の声」「参照音声」も選択できます。
7. 設定を編集したら「変更を反映し再生声」を押します。同じ投稿に「生成待ち」「音声を生成中」と受付からの経過表示を出し、完了したら音声添付に置き換えます。未変更ならボタンは無効です。別案が必要なら詳細設定のseedを変更し、聴き直すだけなら音声の▶を押してください。
8. 気に入ったら「この声に決定」を押します。その候補のWAV原本が登録され、対象キャラクターに割り当てられます。確定まで現在の声は変わりません。Discordフォームからの確定は登録完了の表示だけで、VCやPlayerへの確認音声は流しません。従来のVTTチャット即時登録では確認音声を維持します。

- Discord声デザインの初期試聴セリフは「これからこの声でお話しします。」です。基本設定で編集できます。
- **共同編集です。** 専用チャンネルの参加者は、ほかの人のキャラのフォームも編集できます。本人限定のアクセス制御はありません。音声と設定もチャンネル閲覧者に公開されます。
- 1キャラ1件、全体で4件まで、開始から10分間です。設定編集後は再生成するまで確定できません。基本・詳細の入力ダイアログと試聴メッセージを行き来するUIです。
- 「既存の声」「参照音声」は選択ダイアログを開きます。送信するまでは設定も試聴音声も変わらず、閉じる・キャンセルで戻れます。候補が多い場合は「次の候補を見る」を選んで送信し、案内のボタンで続きを開きます。この案内にも「閉じる」があります。
- 参照音声IDは自動で採番します。キャラ名や読み上げ有効・無効の変更は既存Player／管理画面で行ってください。
- 音声はWAV添付（大きい場合はOgg Opus）です。インライン再生の表示はDiscordのPC・スマホ・形式によって異なります。任意のHTMLプレイヤーは埋め込みません。
- 「取消」、読み上げ全停止、セッション終了、Bot終了、設定変更、Bridge再起動で未完了の声づくりは終了します。古いボタンから復元はできません。VTTから再度登録してください。
- `（ブリッジ声削除）` は引き続き使えます。`（ブリッジ声解除）` も同じ動作です。進行中の試作を中断し、キャラの声の割り当てを外します。登録済み参照音声ファイル自体は削除しません。
- モードが有効なのにBotが未接続・権限不足の場合は登録失敗として扱います。即時登録には自動で切り替わりません。従来の運用に戻す場合は試聴モードをオフにしてください。
- 終了時には投稿から試聴添付を外します。Botの権限不足・切断時には更新できない場合があり、ダウンロード済み音声の消去もできません。

### 入室・退出メッセージ

Botがボイスチャンネルに入ったときと出るときに、メッセージを読み上げます。

- 「入室メッセージ」「退出メッセージ」は各100文字以内です。空欄にしたメッセージは流しません。
- 「声」で登録済みの声を選べます。未設定なら「聞き取りやすい若い女性ナレーターの声」で読み上げます。
- 変えたら「メッセージを保存」を押してください。状態欄に「音声を生成中です」「音声の準備済み」「音声の生成に失敗しました」などが表示されます。
- 「入室を試聴」「退出を試聴」の音は、管理画面だけで鳴ります。
- 接続中に入室メッセージを変えた場合、新しいメッセージは次に接続したときに流れます。
