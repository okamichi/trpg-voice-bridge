# Discord連携

Bridgeが生成した音声を、Discord Botからボイスチャンネル（VC）へ配信できます。VTTの登録コマンドから専用テキストチャンネルに声づくりフォームを開き、参加者が試聴・調整・登録することもできます。

既存VTTのチャットをCollectorで取り込む構成なら、Bridgeをインターネットへ公開せずに使えます。Player・Chatterで直接チャットする参加者には、別途[Bridgeへの接続経路](online.md)が必要です。

## 1. Botを作成して招待する

1. **サーバーを用意する**
   - 既存のサーバーを使う場合、この手順は要りませんが、Botを招待するためにサーバ管理者と同等の権限が必要です。
   - Discordで「サーバーを追加」→「オリジナルの作成」を選び、サーバーを作ります。
     - 新しく作ったサーバーには、デフォルトでボイスチャンネルがあります。
2. **Botを作る**
   1. [Discord Developer Portal](https://discord.com/developers/applications)で、アプリケーションを作成します。
   2. 「New Application」を押し、名前を付けて作成します。名前とアイコンは後から変えられます。
   3. 左のメニューの「Bot」で「Reset Token」を押し、表示されたトークンをコピーします。
      - トークンは一度しか表示されません。なくしたら、もう一度「Reset Token」で作り直してください。
      - パスワードや2段階認証の確認を求められることがあります。
      - 「General Information」の「Public Key」や「Application ID」はトークンではありません。
3. **Botを招待する**
   - 「General Information」の「Application ID」を、次のURLの `<Application ID>` に入れて開きます。
     ```
     https://discord.com/oauth2/authorize?client_id=<Application ID>&scope=bot&permissions=3247104
     ```
   - 開いた画面で対象のサーバーを選び、「認証」を押します。
   - 管理画面でBotにログインしたあとなら、「招待URLをコピー」でも同じURLを取得できます。

```text
https://discord.com/oauth2/authorize?client_id=<Application ID>&scope=bot&permissions=3247104
```

Botのログイン後は、Bridgeの「招待URLをコピー」からも取得できます。

### 必要な権限

| 用途             | 必要な権限                                                           |
| ---------------- | -------------------------------------------------------------------- |
| VCでの読み上げ   | チャンネル閲覧・接続・発言                                           |
| 声づくりフォーム | 専用テキストチャンネルの閲覧・メッセージ送信・ファイル添付・履歴閲覧 |

招待URLは両方を含みます。限定公開のチャンネルではBotのロールにも権限を与えてください。「管理者（Administrator）」権限は付けないでください。Botには不要で、トークンが漏れたときにサーバー全体を操作されてしまいます。

### Developer Portalの設定

| 場所                                    | 設定                 | 説明                                                                                                                                                  |
| --------------------------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 「Bot」の「Privileged Gateway Intents」 | すべてオフ（初期値） | 特権Intentは使わない                                                                                                                                  |
| 「Bot」の「Requires OAuth2 Code Grant」 | オフ（初期値）       | オンにすると上の招待URLで招待できない                                                                                                                 |
| 「Bot」の「Public Bot」                 | オフを推奨           | ほかの人がこのBotを自分のサーバーへ追加できないようにする。オフにするときにエラーが出たら、「Installation」の「Install Link」を「None」にしてから試す |
| 「Bot」の権限一覧（Bot Permissions）    | 触らない             | 招待URLを作るための計算用で、ここで選んでも権限は付かない                                                                                             |

BridgeのBotは通常チャットを収集しません。Interactions Endpoint URLも指定せず、声づくりの操作はGateway経由で受け取ります。

## 2. Bridgeからログイン・接続する

配布アプリでは依存ライブラリが同梱済みです。ソース起動の場合は、先に `tts-bridge/` で次を実行します。

```sh
npm --prefix discord ci
```

1. 管理画面の「2 Discord Bot」で「Discord Botに接続する」をオンにします。
2. Botトークンを入力し、「保存してログイン」を押します。
3. Bot名が表示されたらボイスチャンネルを選び、「接続」を押します。
4. TTSを準備し、キャラの声を設定して「読み上げ開始」を押します。
5. 参加者も同じVCに入り、新しい発言が聞こえることを確認します。

権限のないVCは一覧に「（権限がありません）」と表示され、選択できません。Botの接続先は保存され、接続後は次回起動でも自動接続します。接続中に別のVCを選ぶと、退出メッセージを流してから新しいVCへすぐ移動します。「切断」でも退出メッセージを流し、次回はログインだけになります。

Discordで聞く人はPlayer・Chatterの音声を停止します。ログ閲覧や声設定にはそのまま使えます。ブラウザのキャラ別ミュートはBotへ反映されません。Botの音量は各自のDiscordで調整します。

## Discordで声を作る

v0.5.2で追加された、VTTの登録コマンドから声を試作する機能です。初期状態ではオフで、従来の即時登録から自動では切り替わりません。

### 有効にする

1. 通常のテキストチャンネルを一つ用意し、Botへ声づくりに必要な権限を与えます。
2. BotをBridgeからログインさせます。
3. 「VTTチャットからDiscordで声をデザイン」で専用テキストチャンネルを選び、「登録コマンドで試聴フォームを開く」をオンにして「試聴モードを保存」を押します。
4. 「5 声と読み上げの調整」の「チャットによる登録機能を有効にする」もオンにします。
5. CollectorをVTTへ接続します。

試聴フォームだけならBotのVC接続、Bridgeの外部公開、ポート開放は不要です。通常のセリフをVCで読む場合は、BotのVC接続とBridgeの読み上げ開始が必要です。

### 試聴から確定まで

1. 参加者がVTTで対象キャラとして、次のように公開発言します。

   ```text
   （ブリッジ声登録）イケオジボイス。
   ```

2. 専用チャンネルに出たフォームで、キャラ名を確認して添付音声を聞きます。初期セリフは「これからこの声でお話しします。」です。
3. 「基本設定」で声の名前・説明・速度・試聴セリフ、「詳細設定」でseed・生成ステップ数・CFGを編集します。
4. 必要なら「既存の声」「参照音声」から選びます。選択ダイアログは送信するまで反映されず、閉じる・キャンセルで戻れます。候補が多い場合は次の候補を開きます。
5. 設定変更後に「変更を反映し再生声」を押します。同じ投稿に生成待ち・生成中・受付からの経過が表示され、完了すると音声添付へ置き換わります。
6. 気に入ったら「この声に決定」を押します。試聴した候補のWAV原本を参照音声として登録し、そのキャラへ割り当てます。

別案を作る場合はseedを変えます。聴き直すだけなら添付音声の再生ボタンを使います。設定が未変更なら再生成ボタンは無効です。変更後は再生成するまで確定できません。

確定するまで現在の声は維持します。取消や期限切れでも、既存の割り当ては変わりません。確定時は登録完了を表示し、PlayerやVCへ確認音声は流しません。従来の即時登録は、読み上げ中の確認音声を維持します。

### 共同編集と期限

- フォームは専用チャンネルでの共同編集です。本人のキャラだけに操作を制限する仕組みはなく、音声と設定も閲覧者に公開されます。
- 同時に1キャラ1件、全体4件までです。開始から10分で終了し、編集や再生成では延長されません。
- 同じキャラの試作中は、Player・Chatterからの設定保存などを一時的に制限します。
- 「取消」、「読み上げ停止」、セッション終了、Bot終了、Bridge再起動で未完了フォームは終了します。チャット登録のオフ、TTS接続先の変更、試聴モード設定の保存、「設定を初期値に戻す」でも終了します。古いフォームは使わず、VTTから登録し直してください。
- `（ブリッジ声削除）` と `（ブリッジ声解除）` は試作を中断し、キャラの声の割り当てを外します。参照音声のファイルは消しません。
- Bot未接続・権限不足でも即時登録へ自動では戻りません。即時登録に戻す場合は試聴フォームの設定をオフにします。

試聴はWAV添付を使い、大きい場合はOgg Opusを使います。インライン再生の表示はDiscordクライアントや形式で異なります。終了時には投稿から添付を外しますが、Botが切断中・権限不足の場合は更新できず、ダウンロード済みの音声も消去できません。

声登録・削除・解除に失敗した場合は、管理画面の「チャットによる登録ログ」で理由を確認できます。ログにはこれらの失敗を新しい順に最大5件表示し、24時間で消えます。

## 入室・退出メッセージ

BotがVCへ入るとき・出るときの読み上げを設定できます。本文はそれぞれ100文字以内で、空欄なら流しません。登録済みの声を選び、「メッセージを保存」で反映します。未設定時は既定のナレーター説明を使います。

「入室を試聴」「退出を試聴」は管理画面だけで再生します。接続中に入室メッセージを変更しても、その場ではVCへ流れず、次の接続で使います。

## ボイスチャンネルの発言を文字起こしする

内蔵speech.cppを使うと、Discordの参加者の発言を文字起こしできます。既定は無効で、外部TTSサーバーでは使えません。**ボイスチャンネルの参加者に記録することを伝え、同意を得てから有効にしてください。**

1. 管理画面の「TTSの起動設定」で、起動方式に内蔵speech.cppを選びます。
2. 「文字起こし（STT）」の「一覧からダウンロード」で認識モデルを選び、「ダウンロードして使う」を押します。最初の選択はQwen3-ASR-0.6B Q8_0です。取得済みなら「このモデルを使う」を押します。STTモデルの絶対パスを直接入力することもできます。
3. 「Discordのボイスチャンネルの発言を文字起こしする」をオンにします。
4. 必要なら「文字起こしの書き出し先」に絶対パスを指定します。空欄または「既定に戻す」で、Bridgeの保存先の `transcripts/` を使います。
5. 「次回起動の設定を保存」を押してBridgeを再起動し、「文字起こし：準備完了」を確認します。モデルの取得だけでは設定は保存されません。
6. Botをボイスチャンネルに接続します。保存済みの接続先がある場合は自動接続します。

TTSとSTTのモデルは同じ保存先を使い、一度に1件だけダウンロードできます。「中止」の後は続きから取得できます。一覧にはQwen3-ASR（0.6B・1.7B）、ReazonSpeech v2、Parakeet TDT-CTC 0.6B (ja)のQ8_0・Q6_K・Q5_K・Q4_Kがあります。モデルのライセンスは管理画面の「クレジット」で確認できます。

STTの準備が完了すると、接続中でもBotのスピーカーミュートが解除され、受信を始めます。準備中やエラー時は受信を止め、ミュートに戻ります。無効なときもミュートで接続します。文字起こし中は、Discordの欄に有効状態と、文字起こしした発言の件数を表示します。他のBotとBot自身の発言は記録しません。

文字起こしが有効な間は、Player・Chatter・Collectorから受け付けたチャットのセリフも、Bridgeが受け付けた時刻で同じ記録に追記します。「チャットと本文の共有」をオフにしていても、Collectorから受け付けたセリフは記録します。「卓のチャット履歴を消去」しても、記録からは消えません。発言者はDiscordの表示名で記録し、キャラクター名には対応付けません。マイクを共有する複数人の区別はできません。

### 記録をダウンロードする

Player・Chatterの「音声・再生設定」の下にある「文字起こしデータのダウンロード」を押します。ページの音声を有効にする必要はありません。まだ記録がなければ「まだ文字起こしはありません」と表示します。

ZIPには、時刻順に並べた `transcript.txt` と `transcript.jsonl` が入ります。TXTは、声の発言が `[HH:MM:SS] 名前: テキスト`、チャットのセリフが `[HH:MM:SS] [チャット] キャラ名: テキスト` です。JSONLは1行に1件のJSONで、チャットのセリフには `"type":"chat"` と受け付けた経路（`source`）が入ります。TXTの時刻はBridgeのPCのタイムゾーン、JSONLの時刻はUTCです。「チャットと本文の共有」をオフにしていても、ZIPにはチャットのセリフが含まれます。

参加者なら誰でも、**今回のBridge起動以降の全記録**を取得できます。同じ起動中にセッションを切り替えた場合、前のセッションの記録も含まれます。再起動前の記録はダウンロード対象外です。

### ファイルへの保存と終了

文字起こしは1件ごとに、指定したフォルダーの `transcript-YYYYMMDD-HHMMSS.jsonl` に追記します。起動のたびに別のファイルを作り、終了後も残します。同名があると連番を付けます。ファイルには参加者の発言が残るため、保管先や共有先に注意し、不要になったら削除してください。

正常に終了するときは、最大10秒間、残った発言の文字起こしを待ちます。期限までに文字にできなかった発言は記録されず、その件数をファイルに残します。強制終了では処理中の発言を残せません。順番待ちが200件を超えた場合も、古い発言から捨て、件数を記録します。

### うまく記録できないとき

- 音声合成を優先するため、読み上げが続く間は文字起こしが遅れます。長い発言は30秒ごとに区切り、区切りで単語が切れることがあります。
- Botの読み上げがマイクに回り込んだ発言は除外しますが、参加者の声と混ざると残ることがあります。読み上げと同じ文章を復唱すると除外されることもあるため、ヘッドホンを使ってください。
- 「文字起こしのファイルを書き出せません」と出たら、書き出し先の権限と空き容量を確認してください。書けなかった記録は一時的に保持して再試行しますが、終了後の保存は保証されません。
- STTモデルがない・読めない・認識モデルでない場合は、エラーを表示してSTTを使わずに起動します。モデルの重みの破損などで読み込みに失敗すると、読み上げも起動しないことがあります。その場合は文字起こしを無効にして設定を保存し、Bridgeを再起動してください。

Discordの音声受信は公式に説明されていない機能を利用しているため、Discord側の変更で使えなくなる場合があります。

## 保存・終了・困ったとき

Bot設定とトークンはBridgeの保存先の `discord.json` に保存します。トークンを状態画面へ返さず、通常のログにも出しません。「トークンを削除」で保存したトークンを消してログアウトします。バックアップにも秘密情報が入るため、共有しないでください。

Botを無効にするかBridgeを終了すると接続を閉じます。通常終了では退出メッセージを流しますが、強制終了や接続障害では流せません。切断中のセリフは再接続後にまとめて再生しません。

音が出ない場合は、TTS・読み上げ状態・キャラの声・BotのVC接続・権限を確認します。フォームが出ない場合は、通常のチャット登録とDiscord試聴フォームの両方がオンかを確認してください。詳しい切り分けは[FAQ](faq.md)、Botの単体診断は[Discord Botの詳細と診断](../tts-bridge/discord/README.md)にあります。
