# よくある質問（FAQ）

TRPG Voice Bridgeを使う音声担当者・参加者向けのFAQです。v0.5.2での機能と、現在の実装をもとにしています。画面の手順番号は、起動方法やバージョンによって異なる場合があります。

症状がある場合は、まず管理画面の「接続状態」でTTS・Collector・Discord Bot・Playerを確認してください。声づくりは、設定を一度に変えず、同じセリフで一項目ずつ比較すると原因を切り分けやすくなります。

## 使い方と構成

### 何をするツールですか？

VTTの公開キャラ発言やPlayer・Chatterからの発言を、キャラごとの声で読み上げるツールです。音声担当者のPCで音声を生成し、Player・Chatter、またはDiscordのボイスチャンネルに配信します。

### GMだけが動かすものですか？

音声担当者はGMでもPLでもかまいません。VTTのGM権限も必須ではありません。同じチャットを取り込む担当者は一人に決めてください。

### 参加者全員にTTSモデルやアプリのインストールが必要ですか？

TTSとBridgeを動かすのは音声担当者のPCです。参加者はPlayerをブラウザで開くか、Chatter拡張、Discordを利用します。Chatterを使う人だけは拡張の導入が必要です。

### Bridge、TTS、Collector、Player、Chatterは何が違いますか？

| 名前        | 役割                                                                     |
| ----------- | ------------------------------------------------------------------------ |
| Bridge      | キャラ・声・発言を管理し、音声生成を依頼して配信する                     |
| TTS         | テキストから音声を生成する。内蔵speech.cppまたは対応する外部サーバー     |
| Collector   | 音声担当者が開いたVTTの新しい公開キャラ発言を取得するChrome拡張          |
| Player      | ブラウザで声設定・チャット・音声再生を行う参加者画面                     |
| Chatter     | Playerと同様の機能をChromeのサイドパネルで使う拡張                       |
| Discord Bot | 生成音声をVCで流し、専用テキストチャンネルでは声づくりフォームを提供する |

構成図と導入手順は[セットアップガイド](setup-guide.md)を参照してください。

### Discordは必須ですか？

必須ではありません。テキセでもPlayerやChatterだけでも再生できます。Discordを使う場合も、聞く場所は一つにすると音声の二重再生を避けられます。

### VTTにチャット機能がなくても使えますか？

Player・Chatterからキャラを作成し、直接チャットできます。この使い方ではCollectorは不要です。発言はBridgeの参加者に届きます。

### 参加者にPlayerを公開せずに使えますか？

既存VTTのチャットをCollectorで取り込み、生成音声をDiscord Botから流せば利用できます。声は音声担当者のPlayerで全員分を設定するか、VTTチャットで各人が即時登録し、Discordの声づくりフォームで設定します。

### 自分のマイク音声を文字起こししたり、リアルタイムで声を変えたりできますか？

現在のBridgeはテキスト読み上げを扱います。マイクの文字起こしやリアルタイムのボイスチェンジャー機能は提供していません。

## インストール・起動・モデル

### まず何をダウンロードすればよいですか？

[GitHub Releases](https://github.com/okamichi/trpg-voice-bridge/releases)から、macOS arm64用またはWindows x64用の配布ZIPを選びます。展開後は実行ファイルだけを移動せず、`runtime/` などを含むフォルダー全体で使ってください。[同梱README](../tts-bridge/packaging/README.txt)にも起動手順があります。

### 配布版にNode.jsやPythonは必要ですか？

配布版Bridgeと内蔵speech.cppを使う場合、別途Node.jsやPythonを導入する必要はありません。モデルは同梱していないため、管理画面からダウンロードするか、対応するモデルを指定します。外部TTSを使う場合は、そのTTSに必要な環境を別途用意します。

### ソースから起動するには？

Node.js 22.13以上を用意し、`tts-bridge/` で `npm ci` を実行します。macOS（Apple Silicon）とWindows（x64）では、続けて `npm run package:speech` でspeech.cppをビルドしてから `npm start` を実行します。ビルドにはCMakeとC++のビルド環境が必要です。ほかの環境では、`npm start` だけで外部TTSに接続して使えます。Discordを使う場合は `npm --prefix discord ci` も必要です。詳細は[ビルドと起動](build.md)を参照してください。

### macOSやWindowsが起動を止めます。

macOS版はAppleの公証を受けておらず、Windows版はコード署名がありません。事前にAppleやMicrosoftにアプリの申請が必要だからです。入手元と配布ファイルを確認し、同梱READMEのOS別手順に従ってください。起動できない理由が警告なのか、ファイル欠落なのか、TTSの起動失敗なのかを分けて確認します。

### WindowsでVulkan版が動きません。

Vulkanに対応したGPUとドライバーを確認してください。管理画面で内蔵TTSをCPU版に切り替え、保存後にBridgeを再起動して切り分けられます。CPU版でもAVX2対応CPUが必要で、生成時間はGPU利用時より長くなる場合があります。

### WindowsのCPU版なら、どの古いPCでも動きますか？

配布版のWindows用speech.cppはAVX2を前提にしています。CPU版は高価なGPUが不要という意味で、すべてのCPUに対応する意味ではありません。空きメモリもモデルに応じて必要です。

### Intel MacやLinuxで使えますか？

現在の配布パッケージはmacOS arm64とWindows x64向けです。ほかの環境ではBridgeをソースから起動し、利用環境に対応した外部TTSを用意する構成を検討してください。その場合、内蔵TTSは使えず、外部TTSだけで起動します。配布版と同じ動作保証があるわけではありません。

### モデルはどこで選びますか？

配布版では管理画面の「TTSの準備」にある起動設定・モデル管理を使います。内蔵TTSのモデルを変更したら保存し、Bridgeを再起動して反映します。外部TTSのモデル切り替えは、そのサーバー側の手順にも従ってください。

### モデルは大きいほどよいですか？

モデルによって声質や説明への追従性、必要メモリ、速度が異なります。セッションでは音質と待ち時間の両方を、実際に使うセリフで確認してください。モデルの特徴とリンクは[READMEのモデル案内](../README.md#推奨モデル)にあります。

### モデルのダウンロードに失敗します。

管理画面に表示されたエラー、ネットワーク、保存先の書き込み権限、空き容量を確認してください。保存先を直接指定する場合は絶対パスを使います。ダウンロード中の保存先変更は避け、画面の中止・再試行操作で対応してください。

### オフラインでも使えますか？

必要なモデルと実行ファイルがそろっていれば、内蔵TTSでの生成にクラウドTTSへの接続は不要です。ただし、モデルの初回ダウンロード、オンラインVTT、Discord、別ネットワークの参加者との通信には、それぞれ接続が必要です。

### 管理画面が自動で開きません。

起動した端末に表示された管理用リンクを開いてください。ブラウザの自動起動だけが問題なら `--no-browser` を付けて起動する方法もあります。管理用リンクは参加者に渡すリンクとは異なります。

### 管理画面は開けますが、TTSが未接続です。

Bridgeの起動とTTSの準備は別です。内蔵TTSならモデル・バックエンド・TTSポートを、外部TTSならサーバーの起動状態と接続先を確認します。Bridgeの標準ポートは8090、外部TTSの初期接続先は8088、内蔵TTSの既定ポートは18088です。

### ポートが使用中と表示されます。

同じBridgeやTTSを二重に起動していないか確認してください。別のアプリと重なる場合はBridgeやTTSのポートを変更します。Bridgeのポート変更に合わせ、Collector接続先や参加URLも確認してください。

## VTT・Collector

### Collectorは誰がインストールしますか？

VTTの既存チャットを取り込む音声担当者だけです。CollectorとBridgeは同じPCで動かし、Collectorの接続先には `127.0.0.1` のBridgeを指定します。Player・Chatterで直接会話する場合は不要です。

### どのVTTに対応していますか？

FVTT 12・13・14、ユドナリウム with Fly、対応する従来方式のユドナリウム、ココフォリアの取得処理があります。VTTの版や設置先の内部形式によって取得できない場合があります。[VTTごとの条件](setup-guide.md#collectorとは)を確認してください。

### Collectorを接続したのに以前のログを読みません。

接続後の新しい公開キャラ発言だけを対象にしています。表示済みのチャット履歴をさかのぼって読み上げる機能ではありません。

### 自分の発言が読み上げられません。

対象のチャット・キャラとしての公開発言か、Collectorが接続中か、Bridgeが読み上げ中か、そのキャラに声が設定されているかを順に確認します。声未設定中や停止中の発言は、後から声を設定しても自動では読み直しません。

### FVTTでユーザー名の発言を読みません。

Actor付きのキャラ発言が対象です。「Public as Character」で公開発言してください。「Public as User」、whisper、ブラインド発言、ダイスロールは対象外です。

### ユドナリウムの取得が止まります。

公開範囲や元の発言IDを確認できない場合、推測して取り込まず停止します。Collectorの理由表示を確認し、対応する取得方式・公開チャットを選んでください。Flyでは自動判別できない設置先で取得方式を明示する必要があります。

### ココフォリアのダイスを全部読み上げますか？

ダイスだけの発言や結果は読み上げません。ダイス付きのセリフは、認識できた先頭コマンドを除いた本文を読みます。例えば `1D100 ダイスを振ったわ！` は「ダイスを振ったわ！」が対象です。

### ココフォリアで名前を変えたら声が変わりました。

投稿者と発言者名の組でキャラを区別しています。名前を変えたり、発言する人が替わったりすると別キャラになります。同名でも投稿者が違えば別設定です。

### 秘話やシークレット発言も参加者に配信されますか？

Collectorは確認できた公開キャラ発言を対象にし、秘話・シークレット・宛先付きなどは取り込みません。Player・Chatter自体には秘話機能がないため、そちらへ直接送った発言は卓に共有されます。

### VTTの発言を編集したら音声も修正されますか？

既存発言の編集を再生成する用途には対応していません。訂正したセリフを新しい発言として送ってください。

### Collectorの更新後に接続できなくなりました。

Chromeの拡張管理でCollectorを再読み込みし、VTTのタブも再読み込みしてから接続し直します。接続承認が必要なら、拡張に出た確認コードを管理画面で承認してください。

### CollectorからVTTへチャットを送り返せますか？

送り返しません。Collectorは公開発言の取得用です。Player・Chatterの発言も、VTTの盤面やチャットを変更しません。

## 声の作成・登録・共有

### 声を登録する方法は何種類ありますか？

Player・Chatterの声設定、VTTチャットでの即時登録、VTTチャットを入口にしたDiscordフォームがあります。Discord試聴モードを有効にした場合だけ、VTTの登録コマンドがフォーム開始になります。

### 声の説明には何を書けばよいですか？

「落ち着いた低めの男性の声」「明るく朗らかな女性の声」など、声質や話し方を短く具体的に書きます。思う声から遠い場合は、説明を簡潔にして一つずつ条件を足す方法で比較してください。特定の説明に必ず一致する保証はありません。

### 参照音声がなくても声を作れますか？

説明文による声づくりに対応するモデルなら可能です。Player・Chatterでは参照音声を使わない設定を選び、声の説明を入力します。Bridgeでは `none` などを参照なしとして扱います。外部TTSとモデルも、その使い方に対応している必要があります。

### 「登録済みの声」と「参照音声」は何が違いますか？

登録済みの声は、名前・説明・seed・steps・参照音声IDなどをまとめたBridgeの設定です。参照音声は、TTSが声質の手掛かりにする音声データです。Bridgeの声設定だけコピーしても、別のTTSに参照音声がなければ同じようには生成できません。

### 気に入った試聴音声を、そのまま声の基準にできますか？

Player・Chatterでは試聴後に「この試聴音声を参照音声に登録」を使えます。Discordでは「この声に決定」で試聴した候補の原本を参照音声に登録し、対象キャラへ割り当てます。確定時に新しい試聴候補を作り直す処理ではありません。

### 参照音声に登録すれば、どのセリフも完全に同じ声になりますか？

声質の手掛かりにはなりますが、セリフ・演技・モデル・設定によって結果は変わります。基準にしたい音声自体が不自然なら、その影響も考えられます。複数の短いセリフで試してください。

### 試聴しただけでキャラの声は変わりますか？

試聴だけではキャラの割り当ては確定しません。Player・Chatterでは保存、Discordでは「この声に決定」が必要です。Playerでの参照音声登録と、キャラ設定の保存も別操作です。

### 声を保存したはずなのにセリフを読みません。

声が対象キャラに割り当てられているか、キャラの読み上げが有効か、管理画面が読み上げ中かを確認してください。参照音声だけを登録した状態では、キャラへの割り当ては完了していません。

### 複数キャラに同じ声を使えますか？

同じ登録済みの声を選べます。ただし、Player・Chatterでその共有の声を編集すると、使っているほかのキャラにも反映されます。別々に調整したい場合は新しい声設定を作って割り当ててください。

### Player・Chatter・Discordを同時に使っても混ざりませんか？

設定と候補はキャラ・フォームごとに管理します。Discordフォームで登録中のキャラは、Player・Chatterからの保存・削除を拒否します。別キャラは操作でき、古い画面から変更を上書きしようとすると競合エラーになります。共有の声の編集には、前項の影響があります。

### 「他の人が変更しています」と表示されます。

設定画面を開いた後で、同じキャラや声が更新された場合などに出ます。いったん開き直して最新の状態を確認し、必要な変更だけを入れ直してください。古い画面で保存を繰り返しても解消しません。

### 自分のキャラだけを編集できるようになっていますか？

現在は共同編集を前提にしています。Player・Chatterは卓のキャラ・声を編集でき、Discordでも指定チャンネルの参加者がフォームを操作できます。名前やフォームの表題を確認して操作してください。本人限定の所有権管理はありません。

### VTTチャットの登録コマンドは？

対象キャラとして、対象の公開チャットで次のように発言します。カッコは全角、コマンドは発言の先頭です。管理画面の「チャットによる声登録」を有効にしてください。

```text
（ブリッジ声登録）明るく朗らかな女性の声。
（ブリッジ声削除）
（ブリッジ声解除）
```

削除と解除は同じ動作です。登録には声の説明が必要で、削除・解除の後には余計な文字を付けません。

### 声削除・キャラ削除・登録済みの声の削除は同じですか？

違います。チャットの声削除・解除はキャラの割り当てだけを外します。キャラ削除はキャラ登録を消し、登録済みの声の削除はBridgeの声設定を消します。どちらもTTS側の参照音声ファイルをまとめて削除する操作ではありません。

### 登録数に上限はありますか？

キャラと登録済みの声は、それぞれ500件までです。再登録で声が増えたら、Playerの「登録済みの声を整理」で使っていないものを確認して削除してください。使用中の声は削除できません。

### 不要なキャラを消したのに、また一覧に出てきます。

VTTから新しい公開発言を取得すると、そのキャラを再検出する場合があります。キャラ登録の削除はVTT側のキャラや発言を消す操作ではありません。

## 生成パラメータ

### 生成ステップ数のデフォルトはいくつですか？

Bridgeで新しく声を作る場合の既定値は **20** です。増やすと生成時間が増えますが、精度が上がります。設定可能範囲は **1〜100**。既存の声は保存済みの値を使い、サンプル設定など別の初期値を読み込んだ声は20とは限りません。これはBridgeの既定値で、モデル単体や外部TTSの既定値と同じとは限りません。

### ステップ数はどこで変えますか？

Player・Chatterではキャラの声設定の「声の詳細設定」→「生成ステップ数」、Discordフォームでは「詳細設定」で変更します。試聴で確認した後、保存・確定してください。声ごとの設定です。

### ステップ数を増やせば、ハルシネーションはなくなりますか？

保証はありません。発音の崩れや余計な発声は、モデル・本文・参照音声・説明・CFGなども関係します。ステップ数だけを増やして解決しない場合は、同じ本文・seedでほかの条件を一項目ずつ確認します。増やすほど計算量も増えます。

### 具体的には、どの値を比較すればよいですか？

調整の出発点の例として、現在20なら30、40と段階的に試し、音質と生成時間を比べられます。これは推奨値の保証ではなく比較例です。モデルによって適したステップ数が異なるため、100にすれば最良とは考えず、使用モデルの説明も確認してください。[Irodoriのパラメータガイド](https://github.com/Aratako/Irodori-TTS/blob/main/docs/parameters.md)でも、ステップ数を品質と速度の調整項目として説明しています。

### seedとは何ですか？

生成結果の再現や候補の作り分けに使う乱数の初期値です。同じ説明で別の候補を探したい場合に変更します。音質の点数ではないため、大きな数ほどよい声になる意味ではありません。同じseedでもモデルやほかの設定、実行環境が違えば結果は変わり得ます。

### seedの範囲とデフォルトは？

新規作成時の既定値は `1` です。`0` から `9223372036854775807` までの整数を指定できます。大きなseedは桁を省略せずに入力してください。

### CFGとは何ですか？

読み上げ本文・声の説明・参照音声の各条件を、どの程度強く反映させるかを調整する値です。強すぎると不自然になる場合もあります。いきなり複数を大きく変えず、一項目ずつ試してください。モデルによってはCFGが効かないこともあります。[上流の説明](https://github.com/Aratako/Irodori-TTS/blob/main/docs/parameters.md#classifier-free-guidance)

### 3種類のCFGはどう使い分けますか？

| 項目        | 比較する目的                               |
| ----------- | ------------------------------------------ |
| テキストCFG | 読み上げ本文への追従を調整する             |
| 説明CFG     | 声質・話し方や演技の説明への追従を調整する |
| 参照音声CFG | 参照音声の声質への追従を調整する           |

参照音声を使わない場合、参照音声CFGに効果は期待できません。いずれも「高いほど常によい」という値ではありません。

### CFGの空欄と0は同じですか？

違います。空欄はBridgeからその値を指定せず、TTS側の既定動作に任せます。0は数値の0を明示します。Bridgeでは0〜10を指定できますが、実際の解釈や既定値は利用するTTS・モデルに依存します。

### 話す速度の範囲は？

Bridgeでは0.5〜2、既定値は1です。速度変更がどの程度自然に効くかはTTSにも依存します。極端な設定で崩れる場合は1に戻して比較してください。

### 声の名前を変えると声質も変わりますか？

名前は一覧で見分けるための表示用です。声質を調整するのは説明・参照音声・seedなどです。名前に「低音」と付けるだけでは声の説明を変更したことにはなりません。

### ステップ数やCFGを、全員分まとめて変えられますか？

現在の画面では声ごとに設定します。共有の声を変更すると、それを使うキャラには反映されますが、すべての別々の声を一括変更する機能とは異なります。新規作成の既定値を変えても、保存済みの声は自動更新されません。

### 音質比較をするときのコツは？

本文・モデル・参照音声・seedを固定し、stepsなど一項目だけ変えて比較します。短い挨拶だけでなく、普段の卓で使う長さ・固有名詞・感情を含む複数の文も確認してください。よかった設定値を控えてから次を試すと戻しやすくなります。

## 発音・音質・演技のトラブル

### 入力していない言葉や、謎の声が混ざります。

まず演技指定を外した短い本文で再現するか確認します。声の説明を簡潔にし、参照音声を使っているならその音声も聞き直してください。次にseed、ステップ数、CFGを一項目ずつ比較します。Bridgeには生成結果の内容を自動で検品して、余計な発声を必ず除去する機能はありません。

### 声がザラつく・割れる・ノイズが入ります。

同じ問題が元の試聴音声にもあるか、DiscordやPlayerの出力だけで起きるかを分けます。参照音声とCFGなどの設定を確認し、端末側の音量・出力先も確認してください。配信だけの問題かを切り分けるため、一時的にWAV配信と比較することもできます。

### 固有名詞や漢字の読み方が違います。

試聴では読みをかな・ひらがなに置き換えた本文と比較できます。現在、Bridgeに卓共通の読み辞書を管理する専用UIはありません。ルビのように丸カッコへ読みを書くと、元の語と両方を読む可能性があります。

### 短い試聴ではよいのに、本番の長文では崩れます。

短文一つだけではすべての発音や演技を確認できません。普段のセリフを試聴に入れ、必要なら文を短く分けて送る、句読点を見直す、長文の分割設定を調整する、といった方法で比べてください。

### 声の説明を長く書くほど正確になりますか？

必ずしもそうではありません。矛盾する指示や多くの条件は避け、声質・年齢感・話し方など必要な特徴を短くまとめると比較しやすくなります。Bridgeのcaptionは演技指示込みで上限があるため、長すぎる説明はエラーにもなります。

### 参照音声にはどんな音を使えばよいですか？

同じ話者の声が明瞭に聞こえ、BGM・雑音・ほかの話者が混ざらないものを基準にします。実際に指定した参照音声とモデルの対応も確認してください。[Irodoriの参照音声の説明](https://github.com/Aratako/Irodori-TTS/blob/main/docs/parameters.md#text-caption-and-reference-conditioning)

### 演技指示はどう書きますか？

対応する単語を全角カッコに入れるか、対応する絵文字を本文に書きます。自由な説明は `（演技:震える声で）` のように書きます。

```text
（怒り）ふざけるな！
😲えっ、本当に？
（演技:震える声で、怯えながら）誰か……いるの？
```

詳しい対応表は[演技指示の書き方](../README.md#演技指示の書き方)を参照してください。

### カッコに書いた説明まで読み上げられます。

すべてのカッコが演技指示になるわけではありません。対応単語でも `演技:`・`感情:` 付きでもない `（小さく笑う）` などは本文として扱います。指示にしたい場合は `（演技:小さく笑う）` のように書いてください。

### 演技がほとんど変わりません。

モデルによって効き方が異なります。まず指示なしとの比較を行い、説明CFGや管理画面の「感情・演技の指定方法」を調整して確認します。追記・前置き・置換を切り替えても、モデルが対応しない表現を必ず実現できるわけではありません。

### 演技の「置換」にすると、元の声の設定は消えますか？

保存した声の説明は消えません。その発言の生成時に使う説明を切り替える設定です。置換は参照音声を使う声に適用し、参照なしの声では追記として扱います。

### 絵文字は全部同じように効きますか？

対応表の絵文字でもモデルによって効き方が異なります。表にない絵文字も生成側へ渡る場合がありますが、意図した演技になる保証はありません。Playerの試聴セリフでも比較できます。

### 声優や実在人物そっくりの声を自由に登録してよいですか？

本プロジェクトの[利用上の注意](../README.md#利用上の注意)と、参照音声・モデルそれぞれの利用条件を確認してください。Bridgeのコードのライセンスと、音声やモデルの利用条件は別です。

## 生成待ち・再生・タイムアウト

### 発言したのに音が出ません。最初に何を見ればよいですか？

管理画面でTTS・Collector・参加者の接続状態を確認し、読み上げ中か、キャラの声が設定されているかを確認します。Player・Chatterで聞く人は「音声を有効にする」を押し、端末の出力先・音量・キャラ別ミュートも確認してください。Discordで聞く場合はBotのVC接続を確認します。

### ログは届くのに音声だけ来ません。

チャット本文の共有と音声生成は別です。TTS未接続、声未設定、読み上げ停止、生成キューの混雑などでも本文だけ届く場合があります。ログに表示された音声状態と管理画面のエラーを確認してください。

### 「生成待ち」と「生成中」は何が違いますか？

生成待ちは先行処理が終わるのを待つ状態、生成中はTTSへ生成を依頼して処理している状態です。Bridgeは生成を一つずつ進めるため、複数人の発言や試聴が重なると待ち時間が発生します。

### 残り何秒で生成が終わるか分かりますか？

正確な残り時間の予測表示はありません。Discordフォームには生成準備・生成待ち・生成中と受付からの相対時間を表示します。生成時間はモデル、steps、セリフ、PC、先行処理に依存し、受付からの経過時間は残り時間ではありません。

### 試聴だけがなかなか始まりません。

本番のセリフを優先するためです。60秒待った試聴・声登録は受付順に戻す仕組みがありますが、その時点で必ず完成する意味ではありません。セッション前に声づくりを済ませると混雑を減らせます。

### 生成を速くするには？

stepsを下げる、短い本文で試す、必要メモリや速度が環境に合うモデルを使う、ほかの重い処理を減らす方法を比較できます。内蔵TTSでは利用可能なGPUバックエンドも確認してください。速度だけを優先すると声の安定性や表現が変わるため、本番のセリフで確認します。

### Opus配信にすると音声生成も速くなりますか？

Opusは主に配信データ量を減らす設定です。TTSの生成ステップ数を減らす設定ではありません。ネットワーク転送の改善と生成時間の改善を分けて考えてください。

### 音声の配信形式は何を選べますか？

管理画面からOpus 32・64・96kbps、WAV 256kbps（16kHz）、WAV無圧縮を選べます。既定はOpus 64kbpsです。Opusを再生できないブラウザにはWAVを使う仕組みがあります。DiscordのVC配信や声登録の原本は、このPlayer向けの選択とは別です。

### 「生成処理タイムアウト」になりました。

既定では1回の生成が120秒でタイムアウトします。キュー待ちにも別の期限があります。TTS側の処理状態、空きメモリ、モデル、steps、本文の長さを確認してください。失敗したセリフを自動で生成し直す機能ではありません。

### タイムアウト後、ずっと次の生成が始まりません。

上流で処理が続いている可能性があるため、BridgeはTTSの状態を確認します。10秒ごとの確認で応答が戻れば復帰します。TTS側の処理終了を確認できた場合は管理画面の「Irodori側の処理終了を確認して復帰」を使えます。この操作がTTSのプロセスを強制再起動するわけではありません。

### 生成待ちの上限はありますか？

未完了は原則30件まで、待機期限は180秒です。音声容量の予約でも受付を制限するため、30件より前に上限に達する場合があります。Discordフォーム自体は別途全体4件・開始から10分の制限があります。

### 長いセリフはどう扱われますか？

管理画面の長文分割設定に応じ、句読点などで区切って順番に生成・再生します。既定の分割しきい値は本文150文字、分割パートは最大10です。しきい値を下げても、句読点のない文字列が必ず希望する長さに分かれるわけではありません。

### 文と文の間が長い・短いです。

管理画面の文間の待ち時間を調整してください。既定は900ミリ秒です。これは生成そのものの待ち時間とは異なり、TTSが音声内に作った無音をすべて取り除く機能でもありません。

### PlayerとDiscordで音が二重になります。

Player・Chatter・Discordのうち、音声を聞く場所を一つにします。Discordで聞く人はPlayerやChatterの音声を停止してください。スピーカーの音をマイクが拾う場合は、ヘッドホンなど出力環境も確認します。

### 自分だけ特定のキャラをミュートできますか？

Player・Chatterのキャラ別ミュートは、その再生画面側の設定です。Discord Botには反映されず、ほかの参加者の再生も止めません。Discord側の聞こえ方はDiscordの音量設定で調整します。

### 再参加したら、聞き逃した音声が全部流れますか？

過去の音声をすべて自動再生する仕組みではありません。保持されている音声はログの「もう一度再生」で聞けますが、期限切れや全パートがそろわない場合は再生できません。

### 「もう一度再生」は全員に聞こえますか？

Player・Chatterのログからの再生は、押した本人の画面で聞く操作です。DiscordのVCへ全員向けに流し直す操作とは異なります。

### 音声を後から永久に再生できますか？

音声は期限付きの一時データで、通常の保持は10分、容量上限は512MiBです。チャット本文の保存期間とは別です。長期保存用の音声ライブラリや一括書き出し機能としては使えません。

## Discordでの利用

### Botに管理者権限やMessage Content Intentが必要ですか？

現在の機能には不要です。VCはチャンネル閲覧・接続・発言、声づくり用テキストチャンネルは閲覧・送信・ファイル添付・履歴閲覧を許可します。詳細は[Discordの設定](discord.md)を参照してください。

### Botトークンはどこへ入れますか？

管理画面のDiscord Bot設定に入力します。トークンをチャットやリリースノートへ貼らないでください。保存先の `discord.json` に保持されるため、そのファイルも不用意に共有しないでください。

### Botはログイン済みなのに声を読みません。

ログインとVC接続は別です。管理画面で対象VCへ接続し、Bridgeの読み上げを開始します。キャラの声、TTSの接続、Botの発言権限、参加者側のBotミュートや音量も確認してください。

### Botのチャンネル一覧に、使いたいチャンネルが出ません。

Botがそのサーバーに参加しているか、チャンネルを閲覧できるかを確認します。声づくりには通常のテキストチャンネルを使ってください。VCやスレッドなど、ほかの種類のチャンネルを同じ用途で選べるわけではありません。

### VTTで登録コマンドを送ってもDiscordフォームが出ません。

「チャットによる声登録」と、Discord設定の試聴フォームモードの両方を有効にします。専用チャンネルを保存し、Botのログイン・投稿と添付の権限、Collectorの接続、対象キャラの公開発言かを確認してください。失敗理由は管理画面の登録ログでも確認できます。

### Discord試聴モードを有効にしたのに、Botが使えないとどうなりますか？

登録失敗として扱い、勝手に即時登録へ切り替えません。Botを復旧してからVTTで登録コマンドを送り直すか、試聴モードをオフにして従来の即時登録を利用してください。

### 声づくりフォームを使うだけでもVC接続が必要ですか？

不要です。Botのログインと専用テキストチャンネルへの投稿権限があれば、試聴と声登録ができます。通常のセリフをVCで聞く場合にVC接続が必要です。

### Interactions Endpoint URLにはBridgeのアドレスを入れますか？

入れず、空欄にしてください。Botが音声担当者のPCから張るGateway接続で、ボタンやフォーム送信のイベントを受け取ります。Bridgeへ公開Webhookの受信口を用意する構成ではありません。

### DiscordのフォームはPlayerとまったく同じ画面ですか？

同じ種類の声パラメータを扱いますが、Discord標準のボタン・選択ダイアログ・入力モーダルで操作します。任意のHTMLをチャットに埋め込む機能ではありません。本文には声の名前と説明を表示し、ほかの値は設定画面で確認します。

### 試聴音声はどこに保存・公開されますか？

Bridgeは確定用の原本を一時保持し、Botは試聴用の音声をDiscordに添付します。専用チャンネルを見られる人は試聴できます。終了時には可能な範囲で添付を外しますが、ダウンロード済みのコピーまで消せるわけではありません。

### 再生成するたびに新しい投稿が増えますか？

同じフォームの投稿を更新し、音声を差し替えます。音声を作り直す操作と、今ある音声の再生ボタンで聴き直す操作は別です。

### 「変更を反映し再生声」が押せません。

設定未変更、生成中、登録中などでは無効になります。設定を編集した後に押すボタンです。単に聴き直したい場合は音声の再生ボタンを使います。生成・配信に失敗した場合は再試行できます。

### 「既存の声」「参照音声」の選択は取り消せますか？

選択ダイアログを閉じれば、送信前の選択は反映されません。候補の続きを表示する案内も「閉じる」で消せます。設定を取り込んだ後は、その設定で再生成してから確定します。

### 別の声の候補を試すには？

詳細設定でseedを変更し、「変更を反映し再生声」を押します。声の説明や参照音声も変えられますが、違いを比較する場合は一項目ずつ変えると分かりやすくなります。

### 複数人が各自のキャラを登録できますか？

1キャラ1件、全体で4件まで同時にフォームを開けます。それぞれの設定・試聴音声・登録先を分けています。ただし生成は順番待ちになり、他人のフォームを操作すればそのキャラの設定を変えられる共同編集方式です。

### フォームは放置しても使い続けられますか？

開始から10分で終了します。編集や再生成をしても期限は延びません。終了表示になっていなくても、通信失敗で表示だけ残っている可能性があります。期限切れならVTTで登録コマンドを送り直してください。

### 設定ダイアログを開いている間に、ほかの人が更新したら？

古い版のフォーム送信は拒否されます。元の投稿から開き直して最新の設定を確認してください。確定の連打による二重登録も抑止します。

### Discordで確定したのに、VCに確認音声が流れません。

仕様です。フォームですでに試聴できるため、確定時は登録完了の表示だけにしています。事前試聴のない従来のVTTチャット即時登録では、読み上げ中なら確認音声を配信します。

### Discordの試作中に取り消す方法は？

フォームの「取消」を使うか、VTTで同じキャラとして `（ブリッジ声削除）` または `（ブリッジ声解除）` を送ります。ただしVTTの解除コマンドは試作の中断だけでなく、現在のキャラの声の割り当ても外します。現在の声を維持したい場合はフォームの「取消」を使ってください。

### 読み上げ停止やBridge再起動で、フォームはどうなりますか？

未完了の声づくりは中断します。Botの終了、関連設定の変更、セッション終了でも中断されます。古いボタンから復元はできないため、必要なら登録コマンドを送り直します。

### BotがVCから切断されていた間のセリフは後で流れますか？

切断中のセリフをためて再接続時にまとめて流す運用ではありません。再接続後の新しい発言から利用してください。

### 入退室メッセージを消したり、声を変えたりできますか？

管理画面のDiscord設定で本文と登録済みの声を選べます。本文は各100文字以内で、空欄ならそのメッセージを流しません。変更したら保存してください。入室メッセージの変更は次の接続で使われます。

## Player・Chatter・チャット履歴

### 「音声を有効にする」を毎回押す必要があるのはなぜですか？

ブラウザの音声開始操作と、利用者が聞く場所を選ぶための操作です。再参加やChatterのパネル再表示では音声停止状態から始まる場合があります。Discordで聞く人は、有効にする必要はありません。

### Chatterを閉じても音声は流れ続けますか？

パネルを閉じると通信と再生は止まります。再表示時は履歴を復元し、音声停止状態から始まります。閉じていた間の音声をまとめて自動再生する動作ではありません。

### Chatterはどこから導入しますか？

配布ZIPの `chatter/`、またはPlayer内の導入案内から取得したZIPをChromeの拡張管理で読み込みます。ソース版では先に `npm run chatter:build` を実行します。[詳しい手順](../tts-bridge/chatter/README.md)を参照してください。

### Chatterのコードを変えたのに画面が古いままです。

ソース開発ではChatterを再ビルドし、Chromeの拡張を再読み込みします。Bridgeが配るダウンロードZIPを更新するにはBridgeの再起動も必要です。生成済みファイルを直接編集する運用は避けてください。

### TTSが未接続でもチャットだけ使えますか？

本文共有が有効なら使えます。声未設定や読み上げ停止中でも本文は保存・共有されます。後で音声準備ができても、その間の発言を自動で生成するわけではありません。

### 発言やキャラの下書きは誰に見えますか？

送信した発言は同じ卓のPlayer・Chatterへ共有されます。送信前の下書きやキャラ選択などはブラウザ側に保存するものがあります。Player・Chatterには相手を限定する秘話機能はありません。

### チャット履歴はどのくらい残りますか？

BridgeのDBに直近7日、卓ごとに最大10,000件を保存します。画面には最新100件までを表示します。本文の保存期間と、音声ファイルの保持期限は別です。

### 「チャットと本文の共有」をOFFにすると履歴も消えますか？

送信・本文閲覧を停止する操作で、保存済み履歴の消去ではありません。消す場合は管理画面の「卓のチャット履歴を消去」を使います。

### 履歴を消去すれば、再生中の音声も止まりますか？

履歴消去と音声停止は別です。必要なら読み上げも停止してください。セッション終了や読み上げ停止だけで、保存済みの本文が消えるわけでもありません。

### Enterで改行できますか？

Player・ChatterのチャットはEnterで送信、Shift+Enterで改行します。長文は文字数上限にも注意してください。

### 発言の文字数に上限はありますか？

本文は500コードポイントまでです。絵文字などを含む場合、見た目の文字数と数え方が一致しないことがあります。音声用の分割設定を変えても、この受付上限をなくすわけではありません。

### ブラウザを閉じたら、Chatterで再参加を求められました。

参加資格はブラウザのセッション内で保持します。ブラウザ終了、拡張再読み込み、Bridge再起動、セッション終了、参加資格の期限切れなどでは招待での再参加が必要です。Chatterの「退出・接続先を変更」でも参加資格を失効させます。

## ネットワーク・参加URL

### 参加者に `127.0.0.1` のリンクを渡してよいですか？

`127.0.0.1` は開いた人自身のPCです。別PCの参加者には、音声担当者のBridgeへ届くアドレスを含む参加URLが必要です。音声担当者のPC上で使う場合だけローカルURLを使います。

### 別のPCからPlayerを使うには？

Bridgeの待ち受けアドレス・公開Originと、LANやルーター・ファイアウォールの到達経路を設定します。`0.0.0.0` に変えるだけでインターネットから到達できるとは限りません。[Playerの公開](online.md)を参照してください。

### 公開Originには何を書きますか？

参加者が使うURLのスキーム・ホスト・必要なポートを書きます。例は `https://voice.example.com` や `http://203.0.113.10:8090` です。`/player/` や招待トークンを含む参加URL全体を貼る欄ではありません。

### `0.0.0.0` をブラウザで開けばよいですか？

待ち受け対象を表す設定値です。参加者へ渡す接続先には、実際に到達可能なPCのアドレスやドメイン名を使ってください。

### Discordで聞く場合もポート開放が必要ですか？

既存VTTのチャットをCollectorで取り込み、声設定を音声担当者のPlayerやDiscordフォームで行うなら、参加者からBridgeへ直接接続する必要はありません。Player・Chatterで直接チャットする人がいる場合は、その人からの到達経路が必要です。

### Player・Chatterは自動でNAT越えしますか？

現在はBridgeへのHTTP・WebSocket接続を使います。VTTのSkyWayやWebRTCに便乗して、自動的にNAT越えする機能は実装していません。

### 同じ家のLANでも接続できません。

音声担当者のLANアドレス、Bridgeの待ち受け、PCのファイアウォールを確認します。Wi-Fiの端末間通信が制限される環境もあります。接続テストはそのLANから到達できるアドレスで行い、設定変更後は参加URLをコピーし直してください。

### インターネットからだけ接続できません。

公開Origin、ルーターの転送先、外側と内側のポート、ファイアウォールを確認します。回線側のNATなどで外からの着信ができない場合もあり、ルーター設定だけで必ず解決するとは限りません。

### HTTPSやリバースプロキシを使えますか？

使う場合は公開Originを参加者向けのHTTPS URLに合わせ、WebSocketも転送してください。外部からの要求のHostを管理用ローカルHostへ書き換える構成にはせず、管理機能のローカル制限を維持してください。HTTPのままでは通信は暗号化されません。

### 管理画面も参加者向けURLで開けばよいですか？

管理画面は音声担当者のローカルURLから使います。参加者へ渡すのは参加URLです。管理用リンクやBotトークンを参加者へ渡す必要はありません。

### 参加URLはいつまで使えますか？

招待リンクは1時間です。交換後の参加資格は12時間またはセッション終了までで、招待リンクそのものの期限とは別です。Bridge再起動でも参加し直しになります。期限切れなら管理画面から新しい参加URLをコピーしてください。

### 「参加URLを再発行」で、今いる人も退出しますか？

古い招待リンクからの新規参加を止める操作です。参加済み端末の資格も失効させたい場合は「セッション終了」を使い、再開時に新しい参加URLを配ってください。

### 再起動したら参加できなくなりました。

Bridge再起動で古い招待や参加資格は使えなくなります。管理画面を開き直し、新しい参加URLを渡してください。再起動後の読み上げは停止状態から始まります。

### Collectorのリンクだけ外部アドレスに変えてよいですか？

CollectorとBridgeは同じPCで、`127.0.0.1` の接続を使います。外部URLを使う参加者のPlayer・Chatterとは接続先の役割が異なります。

### スマホやChrome以外のブラウザで使えますか？

PlayerはWebページですが、音声形式・自動再生・バックグラウンド時の動作はブラウザや端末に依存します。使用する端末で試してください。Collector・ChatterはChrome拡張として案内しており、ほかのブラウザで同じ導入手順や動作を保証するものではありません。

## 保存・バックアップ・更新

### 声や卓のデータはどこに保存されますか？

配布版の既定はmacOSが `~/Library/Application Support/TRPG-Voice-Bridge/data/`、Windowsが `%LOCALAPPDATA%\TRPG-Voice-Bridge\data\` です。ソースからの通常起動は `tts-bridge/data/` が既定です。管理画面や起動オプションで変更している場合は、実際の保存先を確認してください。

### バックアップは何をコピーすればよいですか？

Bridgeを終了してからデータディレクトリ全体をコピーします。DBだけでなく、内蔵TTSの `voices/`、`runtime.json`、Discord設定なども対象です。モデルの保存先、起動設定の `startup.json`、外部TTSの参照音声は別の場所の場合があるため、必要に応じてそれぞれ控えてください。

### 別のPCへ移すとき、DBだけで足りますか？

参照音声も使うなら足りません。BridgeのデータとTTS側の参照音声をそろえ、モデルや絶対パス、TTS接続先を移動先に合わせてください。モデルは再ダウンロードすることもできます。保存先には認証情報も含まれるため、受け渡し先を確認します。

### キャンペーンごとに声や設定を分けられますか？

データの保存先を分けられます。管理画面の「起動設定」で保存先を変更して再起動するか、起動時に `--data-dir` などで指定します。外部TTSを使う場合は、その参照音声の保存先も卓ごとに分けると整理しやすくなります。

### 保存先を変えると、元のデータも移動しますか？

移動も削除もしません。切り替え先の保存先で起動します。元の保存先へ戻せば、そのデータを利用できます。保存先変更はバックアップや自動移行の操作ではありません。

### 起動設定を保存したら、すぐ反映されますか？

待ち受け・保存先などは「保存して再起動」、TTS起動設定は保存後の「Bridgeを再起動」で反映します。起動オプションや環境変数で固定した項目は、画面で変更できない場合があります。

### `config.json` を変えて再起動しても反映されません。

通常はDBに保存した設定を使います。初期設定ファイルは、その保存先にDBを初めて作る場合や、設定を初期値へ戻す場合に使います。運用中の声変更は画面から行ってください。

### 「設定初期化」と「設定を初期値に戻す」は同じですか？

対象が異なります。起動設定内の初期化は保存先・待ち受けなどの起動設定を既定に戻して再起動します。キャラ・声の初期化は、それらを設定ファイルの初期値へ戻す操作です。データディレクトリを物理的に全部削除する操作とは区別してください。

### 「セッション終了」と「Bridgeを終了」は何が違いますか？

セッション終了は参加者やCollectorの接続を閉じ、参加資格を失効させます。Bridge自体は動き続けます。Bridgeを終了するとサーバーが停止し、配布版が管理する内蔵TTSも終了します。どちらも履歴を一括消去する操作ではありません。

### 更新するときに気を付けることは？

Bridgeを終了し、データをバックアップしてから新しい配布ZIPを別フォルダーへ展開します。同じデータを使う場合は保存先を確認してください。Collector・Chatterも同じリリースのものへ更新し、拡張とVTTタブを再読み込みします。再起動後は参加URLを配り直します。

### 参照音声が見つからないと表示されます。

使っているTTSが変わっていないか、参照音声の保存先とIDが正しいかを確認します。別PC・別モデル環境へ移した場合は、Bridgeの声設定だけでなくTTS側の音声データも必要です。復旧できなければ、参照なしの新しい声を試作して登録し直す方法もあります。

### 同じ保存先でBridgeを二つ起動できますか？

配布版では同じ保存先の二重起動を防止します。別々の卓を同時に動かす場合は、データ保存先だけでなくBridgeやTTSのポートも分ける必要があります。

### 保存した音声やチャットは自動で外部クラウドに送られますか？

内蔵TTSはローカルで生成し、BridgeのDBや一時音声も音声担当者のPCに保存します。参加者への配信、DiscordのVCや音声添付、外部TTSの指定先には、その機能に必要な情報が送られます。「ローカル生成」は、すべての通信がなくなる意味ではありません。

## 問い合わせ

### 困ったときは何を報告すればよいですか？

Bridgeと拡張のバージョン、OS、CPU・GPU、内蔵／外部TTS、モデル名、操作手順、表示されたエラー、再現する短いセリフをまとめてください。声の問題ならseed・steps・CFG・参照音声の有無も役立ちます。Botトークン、管理用リンク、参加URL、未公開のチャット本文は伏せてください。

### 問い合わせ前に試す最小の切り分けは？

1. 管理画面で接続状態を確認する。
2. 演技指定なしの短いセリフを、一つの声で試聴する。
3. 試聴は成功するなら、Collectorから新しい公開発言を取り込めるか確認する。
4. Player・Chatter・Discordのうち一か所だけで再生する。
5. 同じ条件で再現するか確認し、エラーと操作を控える。

試聴自体が失敗する場合はTTS・モデル・設定、試聴は成功して公開発言だけ失敗する場合はCollectorやキャラの紐付け、生成後の再生だけ失敗する場合は配信先やブラウザの状態を中心に確認します。
