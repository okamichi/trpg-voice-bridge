# Playerの公開

`127.0.0.1` のURLは、開いたPC自身を指すので、音声担当者のPCでしか開けません。別のPCの参加者にPlayerを使ってもらうには、この文書のとおりにBridgeを起動します。

Discord Botだけで音声を流し、キャラの声を音声担当者が設定する場合は、公開する必要はありません（[Discordでの利用方法](discord.md)）。

## 起動のしかた

次の2つの環境変数を指定して起動します。

| 環境変数            | 値                                                                                       |
| ------------------- | ---------------------------------------------------------------------------------------- |
| `TTS_BRIDGE_HOST`   | `0.0.0.0`（PCのすべてのネットワークで待ち受ける）                                        |
| `TTS_PUBLIC_ORIGIN` | 参加者がブラウザで開くURLの `http://アドレス:ポート` の部分。末尾に `/` やパスは付けない |

`TTS_PUBLIC_ORIGIN` のアドレスは、参加者の場所によって変わります。

- 同じLANの参加者だけなら、音声担当者のPCのLANのIPアドレス（例：`192.168.1.10`）。
- インターネットの参加者がいるなら、ルーターのグローバルIPアドレス（例：`203.0.113.10`）。ルーターの管理画面などで確かめられます。

参加者は全員、`TTS_PUBLIC_ORIGIN` のアドレスで開きます。ほかのアドレスで開くと、Bridgeは接続を断ります。

インターネットの参加者がいる場合の例です。

```sh
# macOS など（npm start）
TTS_BRIDGE_HOST=0.0.0.0 TTS_PUBLIC_ORIGIN=http://203.0.113.10:8090 npm start
```

```powershell
# Windows PowerShell（npm start）
$env:TTS_BRIDGE_HOST = '0.0.0.0'
$env:TTS_PUBLIC_ORIGIN = 'http://203.0.113.10:8090'
npm start
```

ダウンロードしたアプリでは、`npm start` を `./trpg-voice-bridge`（Windowsでは `.\trpg-voice-bridge.exe`）に替えます。

## ルーターの設定

インターネットの参加者がいる場合は、ルーターで、外からのTCPの8090番を、音声担当者のPCの8090番へ転送します。ルーターによって「ポートフォワーディング」「ポート開放」「静的NAT」など呼び方が違います。

- 外側のポートを8090以外にした場合は、`TTS_PUBLIC_ORIGIN` には外側のポートを書きます。
- PCのファイアウォールが8090番への接続を止めていないかも確かめてください。
- プロバイダーの契約によっては、ルーターで転送しても外から接続できないことがあります。
- グローバルIPアドレスが変わったら、`TTS_PUBLIC_ORIGIN` を変えて起動し直してください。

## 参加URLを渡す

1. 管理画面は、今までどおり起動ログの管理用リンク（`http://127.0.0.1:8090`）で開きます。外のアドレスでは管理画面は開けません。
2. 「4 卓の開始」の「参加URLをコピー」でコピーしたURLが、`TTS_PUBLIC_ORIGIN` のアドレスになっていることを確かめて、参加者に渡します。
3. 参加者に、参加URLを開いて「音声を有効にする」を押してもらいます。

Bridgeを起動し直すと、それまでの参加URLは使えなくなります。起動し直したら、参加URLをコピーし直して渡してください。

## 公開されるもの

- 外のアドレスから使えるのはPlayerだけです。管理画面とCollectorの接続は、`127.0.0.1` のURLでしか受け付けません。Collectorの「Bridge接続先」も `http://127.0.0.1:8090` のままにしてください。
- 参加URLを知っている人は、誰でも参加できます。卓の参加者にだけ渡してください。「参加URLを再発行」を押すと、以前のURLでは新しく参加できなくなります。
- TTSは公開されません。内蔵TTSは `127.0.0.1` だけで待ち受けます。外部TTSを起動するときも `--host 127.0.0.1` のままにしてください。
- HTTPでは、通信は暗号化されません。暗号化したい場合は、HTTPSのリバースプロキシを前に置き、`TTS_PUBLIC_ORIGIN` にそのHTTPSのURL（例：`https://voice.example.com`）を指定します。同じPCのプロキシから転送するなら、`TTS_BRIDGE_HOST` は指定せず、Bridgeは `127.0.0.1` で待ち受けたままにします。
