# Playerの公開

`127.0.0.1` のURLは、開いたPC自身を指すので、音声担当者のPCでしか開けません。別のPCの参加者にPlayerやChatterを使ってもらうには、この文書のとおりにBridgeを起動します。

Discord Botだけで音声を流し、キャラの声を音声担当者が設定する場合は、公開する必要はありません（[Discordでの利用方法](discord.md)）。

## 起動のしかた

管理画面の「0 起動設定」で次の2つを設定し、「保存して再起動」を押します。Bridgeが再起動し、管理画面も開き直されます。設定は次に起動したときも使われます。

| 項目             | 値                                                                                       |
| ---------------- | ---------------------------------------------------------------------------------------- |
| 待ち受けアドレス | `0.0.0.0（ほかのPCからも接続できる）`                                                    |
| 公開Origin       | 参加者がブラウザで開くURLの `http://アドレス:ポート` の部分。末尾に `/` やパスは付けない |

公開Originのアドレスは、参加者の場所によって変わります。

- 同じLANの参加者だけなら、音声担当者のPCのLANのIPアドレス（例：`http://192.168.1.10:8090`）。
- インターネットの参加者がいるなら、ルーターのグローバルIPアドレス（例：`http://203.0.113.10:8090`）。ルーターの管理画面などで確かめられます。

参加者は全員、公開Originのアドレスで開きます。ほかのアドレスで開くと、Bridgeは接続を断ります。

### 環境変数で指定する

起動するときに環境変数で指定することもできます。環境変数で指定した項目は、「0 起動設定」では変更できません。

| 環境変数            | 値                     |
| ------------------- | ---------------------- |
| `TTS_BRIDGE_HOST`   | `0.0.0.0`              |
| `TTS_PUBLIC_ORIGIN` | 上の公開Originと同じ値 |

インターネットの参加者がいる場合の例です。

```sh
# macOS など（npm start）
TTS_BRIDGE_HOST=0.0.0.0 TTS_PUBLIC_ORIGIN=http://203.0.113.10:8090 npm start
```

```powershell
# Windows PowerShell（npm start）
$env:TTS_BRIDGE_HOST = '0.0.0.0'
$env:TTS_PUBLIC_ORIGIN = 'http://203.0.113.10:8090'
npm start
```

ダウンロードしたアプリでは、`npm start` を `./trpg-voice-bridge`（Windowsでは `.\trpg-voice-bridge.exe`）に替えます。

## ルーターの設定

インターネットの参加者がいる場合は、ルーターで、外からのTCPの8090番を、音声担当者のPCの8090番へ転送します。ルーターによって「ポートフォワーディング」「ポート開放」「静的NAT」など呼び方が違います。

- 外側のポートを8090以外にした場合は、公開Originには外側のポートを書きます。
- PCのファイアウォールが8090番への接続を止めていないかも確かめてください。
- プロバイダーの契約によっては、ルーターで転送しても外から接続できないことがあります。
- グローバルIPアドレスが変わったら、公開Originを変えて「保存して再起動」を押してください。

## 参加URLを渡す

1. 管理画面は、今までどおり起動ログの管理用リンク（`http://127.0.0.1:8090`）で開きます。外のアドレスでは管理画面は開けません。
2. 「4 卓の開始」の「参加URLをコピー」でコピーしたURLが、公開Originのアドレスになっていることを確かめて、参加者に渡します。
3. 参加者に、参加URLを開いて「音声を有効にする」を押してもらいます。

Bridgeを起動し直すと（「0 起動設定」や「Bridgeを再起動」での再起動を含む）、それまでの参加URLは使えなくなります。起動し直したら、参加URLをコピーし直して渡してください。

## 公開されるもの

- 外のアドレスから使えるのはPlayerとChatterの参加者用機能です。管理画面とCollectorの接続は、`127.0.0.1` のURLでしか受け付けません。Collectorの「Bridge接続先」も `http://127.0.0.1:8090` のままにしてください。
- 参加URLを知っている人は、誰でも参加できます。卓の参加者にだけ渡してください。「参加URLを再発行」を押すと、以前のURLでは新しく参加できなくなります。
- TTSは公開されません。内蔵TTSは `127.0.0.1` だけで待ち受けます。外部TTSを起動するときも `--host 127.0.0.1` のままにしてください。
- HTTPでは、通信は暗号化されません。暗号化したい場合は、HTTPSのリバースプロキシを前に置き、公開OriginにそのHTTPSのURL（例：`https://voice.example.com`）を指定します。同じPCのプロキシから転送するなら、待ち受けアドレスは `127.0.0.1` のままにします。
