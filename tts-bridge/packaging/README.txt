TRPG Voice Bridge

FVTT・ユドナリウム・ココフォリアなどのVTTから音声担当者（GMまたはPL）のブラウザ拡張で公開発言を取り込み、Irodori-TTS-Server (あるいはspeech.cpp) で発言テキストの音声生成を動的に行って、参加者のブラウザへ、あるいは Discord Bot 経由で同じ音声を配るためのシステムです。

ビルド済みパッケージ版には Irodori-TTS-Server 互換に修正を加えたフォーク版 speech.cpp を同梱しています。管理画面の「TTSの起動設定」から対応音声生成モデルをダウンロードもできます。

■ 起動方法

macOS: ターミナルで ./trpg-voice-bridge
Windows: trpg-voice-bridge.exe
  
管理画面が標準ブラウザで開きます。終了は管理画面の「6 終了」→「Bridgeを終了」か、起動した端末でCtrl+C。

自動で開けない場合は端末から --no-browser を付けて起動し、表示した管理用リンクを開きます。
管理用リンクは共有しないでください。出力をファイルへリダイレクトするとリンクは表示しません。

データの保存先:
 macOS: ~/Library/Application Support/TRPG-Voice-Bridge/data/
 Windows: %LOCALAPPDATA%\TRPG-Voice-Bridge\data\

設定や声などの保存先は、起動時に `--data-dir` で指定できます。卓ごとに分けるといいでしょう。
指定したフォルダがなければ、起動時に自動で作られます。

```
# macOS
./trpg-voice-bridge --data-dir ./data

# Windows（PowerShell）
.\trpg-voice-bridge.exe --data-dir ./data
```

デフォルトではローカルアドレス 127.0.0.1 のポート番号 8090 で起動します。

生成音声を Discord Bot から発声させる場合は、あなたが卓の参加者全員分の声の設定を行う（あるいは後述の「チャットによる声登録」機能を利用する）ことで、このサーバをインターネットに公開しないようにすることもできます。

参加者にインターネットからサーバにアクセスさせるには、たとえば次のように起動します。

```
## 例えばグローバルアドレスが203.0.113.10で、ルータなどで8090番をNATさせる場合

# macOS
TTS_BRIDGE_HOST=0.0.0.0 TTS_PUBLIC_ORIGIN=http://203.0.113.10:8090 ./trpg-voice-bridge --data-dir ./data

# Windows（PowerShell）
$env:TTS_BRIDGE_HOST = "0.0.0.0"; $env:TTS_PUBLIC_ORIGIN = "http://203.0.113.10:8090"; .\trpg-voice-bridge.exe --data-dir ./data
```

管理画面と後述のCollectorはこれまでどおり http://127.0.0.1:8090 を使います（外部のアドレスでは管理画面は開けません）。

起動オプション:
  --help / --version
  --data-dir <path>     設定・DB・生成音声の保存先
  --port <1-65535>      Bridge待受ポート（既定8090）
  --tts <external|bundled>  今回だけ起動方式を指定
  --model <absolute.gguf>   今回だけGGUFモデルの絶対パスを指定
  --tts-port <1-65535>      今回だけ内蔵TTSポートを指定（既定18088）
  --tts-backend <vulkan|cpu>  Windowsで今回だけ内蔵TTSの種類を指定
  --no-browser         管理画面を手動で開く
  --self-test          SQLite・Discord依存・PCM→Opus変換の診断（通信しません）

・runtime.jsonに起動方式・モデルパス・TTSポートを保存します。起動オプションでの指定は保存値を上書きしません。
・内蔵TTSは127.0.0.1だけで待ち受け、参照音声はdata-dirのvoices/へ保存します。
・バックアップ・移行はBridge終了後にdata-dir全体をコピーしてください。モデルは移動先で別途指定します。
・TTS_DATA_DIR / TTS_BRIDGE_PORT / TTS_CONFIG_FILE 等の環境変数も利用できます。

■ チャットのないVTTで使う（Player / Chatter）

D&D Beyond Mapsなどにチャットを追加する場合、Collectorは不要です。
管理画面で参加URLを発行し、全員が同じBridgeの卓へ参加してください。
TTS・モデルの準備前や、読み上げ停止中も本文の送受信ができます。

・Player：参加URLをブラウザで開く。拡張のインストールは不要です。
・Chatter：VTTの隣のChromeサイドパネルで使う場合に、各参加者が導入します。
・Collector：既存VTTの公開チャットを取り込む場合だけ音声担当者一人が導入します。

Chatterの導入:
1. Chromeで chrome://extensions を開き、デベロッパーモードを有効にします。
2. 「パッケージ化されていない拡張機能を読み込む」で同梱の chatter/ を選びます。
   必要なコードはビルド済みです。Node.jsやnpmは不要です。
3. VTTを開いてChatterのアイコンを押し、管理者から受け取った招待リンクを貼って参加します。
   選んだ接続先へのアクセスを許可します。別PCからは共有された公開URLを使います。
4. 「＋キャラ作成」でキャラを作り、発言キャラを選んで送信します。
   声は「キャラ・声設定」で設定できます。音声を聞く画面だけ「音声を有効にする」を押します。

Chatter・Player・Discordで同時に音声を有効にすると二重に聞こえます。
Chatterは閉じると通信・再生を止め、開き直すと履歴を復元して音声停止から始まります。
「退出・接続先を変更」で参加資格を失効させます。ブラウザ終了後は招待で再参加します。
更新したZIPでは、新しい chatter/ をChromeに読み込み直してください。
詳しくは同梱の chatter/README.md を参照してください。

本文の共有と保存:
発言は同じ卓のPlayer・Chatter参加者に共有され、後から参加した人も閲覧できます。
本文はBridgeのDBに直近7日・卓ごとに最大10,000件を保存します。秘話機能はありません。
「チャットと本文の共有」をOFFにすると参加者の送信・本文閲覧を止めますが、保存済み本文は消えません。
「卓のチャット履歴を消去」で卓全体の本文を消し、接続中画面にも反映します。
音声生成・配信は別に停止してください。「読み上げ停止」「セッション終了」だけでは本文は消えません。
「もう一度再生」は保存期間内の音声を押した本人だけに流し、他の参加者やDiscordへ再配信しません。

■ 管理画面

ページ上部の「接続状態」で、TTS・Discord Bot・Collector・Playerの状態を確認できます。
その下に、設定する順に手順が並んでいます。対応が必要な手順は開いた状態で表示します。

簡単な設定方法

1. TTSの準備：起動方式、モデルのダウンロード、外部TTSの接続先

管理画面の「1 TTSの準備」→「TTSの起動設定」で、起動方式を「内蔵speech.cpp」にします。Windowsでは起動方式に「内蔵speech.cpp（Vulkan）」と「内蔵speech.cpp（CPU）」が出ます。GPUがあればVulkan、なければCPUを選んでください。

「一覧からダウンロード」の「モデル」で使うモデルを選び、「ダウンロードして使う」を押します。ダウンロードが終わると、そのパスが「GGUFモデルの絶対パス」に入ります。手元にあるGGUFを使う場合は、その絶対パスを「GGUFモデルの絶対パス」に貼り付けます。

「次回起動の設定を保存」を押し、「Bridgeを終了」で終了してから起動し直し、状態が「準備完了」になるのを確認します。

2. Discord Bot：使う場合だけ

Discord Bot経由で生成音声を再生する場合は、Discord Bot の設定をDiscord側と管理画面から行います。

Discord 側の設定後に、発行されたBotトークンを指定して「保存してログイン」をし、参加可能なボイスチャンネルのリストから入室するボイスチャンネルを選択して、設定を行ってください。

詳細は https://github.com/okamichi/trpg-voice-bridge/blob/main/docs/discord.md を参照してください。

3. Collectorの接続：VTTの既存チャットを取り込む場合だけ。導入方法、初回接続の承認

セッションを行うVTTにログイン・入室してチャットの画面を確認し、管理画面の「3 Collectorの接続」にある「Collectorの導入」の手順に従って、Collector の拡張機能を入れてください。

その後、VTTのタブでブラウザの拡張機能から「TRPG Voice Collector」を開き、「このタブを接続」を押します。初回は確認コードが表示されるので、管理画面で同じコードを「承認」し、VTTの拡張へ戻って「このタブを接続」を押します。

チャットタブが複数ある場合は、デフォルトではメインタブを使用することになります。

4. 卓の開始：参加URLのコピー、読み上げ開始

管理画面の「参加URLをコピー」を押して、参加URLを卓の参加者に伝えます。参加URLの有効時間は1時間です。管理画面を開いている人は「Playerを開く」でも参加できます。

管理画面の「読み上げ開始」を押すと、音声合成システムの処理が開始されます。

参加者の開始手順：

1. 参加URLを開き、「音声を有効にする」を押す。
2. キャラとしてチャットで一度、公開発言する。最初の発言でPlayerの「キャラの声」にキャラが表示されるので、「声を選ぶ」で声を作成・試聴して「保存」する。

5. 声と読み上げの調整：必要なら

各種設定ができます。

ここでチャットによる声登録をオンにした場合は、「参加URL」を開かなくても声の登録・削除はチャットから簡易的にできるようになりますが、通常は「参加URL」を開かないと参加者はブラウザで生成音声を聴くことができません。

しかし、Discord Bot のボイスチャットを組み合わせて利用することで、生成音声をボイスチャットに流すことができるため、「参加URL」を開かなくても（すなわちインターネットにBridgeサーバを公開しなくても）、管理画面の操作だけで設定作業を完結させることも可能です。

6. 終了：セッション終了、Bridgeを終了

終了する場合は、この設定項目の「Bridgeを終了」を押すか、起動したターミナルでCtrl+Cを押します。内蔵の音声生成もアプリと一緒に停止します。

初期化

声の紐付けなどの内部のデータを初期化することができます。


■ 起動時の警告について

macOS版はAppleによる公証を受けていません。Windows版はコード署名がありません。
初回起動時にOSの確認や警告が表示される場合があります。

macOSで開発元を確認できない旨の警告が出た場合:
  入手元と同梱のSHA-256を確認し、起動を試した後で、
  「システム設定」→「プライバシーとセキュリティ」の「このまま開く」を確認してください。
  Bridgeだけでなく、runtime/speech内のspeechやbridge-supervisor、ネイティブ依存にも
  確認が必要な場合があります。
  Appleの案内: https://support.apple.com/ja-jp/102445

参加者はPlayerの「Chatterの導入について」からChatterのZIPと導入手順を入手できます。
