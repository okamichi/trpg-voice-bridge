# TRPG Voice Bridge

Node.js **22.13以上**。trpg-voice-bridgeは`main.mjs`で起動します。依存はWebSocketの`ws`、設定・認証・発言台帳の保存先はNode組込みSQLiteです。

構成と音声担当者・参加者それぞれの操作は[セットアップガイド](../docs/setup-guide.md)を先に参照してください。Collectorは音声担当者用のブラウザ拡張です。GMでもPLの一人でも担当できます。コードは`collector/`に含まれ、ほかの参加者にはインストール不要です。

## 起動

```sh
cd tts-bridge
npm ci
npm start
```

1. 起動ログの管理用リンクを開き、Irodoriの接続状態を確認します。管理用リンクは共有しません。
2. Chromeの拡張機能画面から`collector/`を読み込み、VTTのタブで「このタブを接続」を押します。初回は管理画面で確認コードを承認し、拡張からもう一度接続します。
3. VTTの種類・入力元ID・FVTTのワールドID・対象チャットは自動取得します。ユドナリウムでは部屋の識別名を入力します。管理画面への入力元登録は不要です。
4. 管理画面の「参加URLをコピー」で共有します。音声担当者自身は「Playerを開く」を使います。
5. 各参加者はPlayerで音声を有効にします。VTTでキャラとして公開発言すると、Playerのキャラ一覧に表示されます。全員が声を選択・試聴・保存できます。
6. 管理画面で「読み上げ開始」。以後の新しい発言を読み上げます。オンライン配信には[HTTPSの設定](../docs/online.md)が必要です。

初期値は`config.json`、保存先は`data/bridge.sqlite`です。接続した卓のキャラを公開発言から検出するため、非公開NPCの一覧を取得・配信しません。同名でもキャラIDが異なれば別キャラです。

**VTT取得の現在地:**

| ツール | 実装・制約 |
| --- | --- |
| FVTT 12/13/14 | 拡張から`createChatMessage`を登録。公開IC・Actor付きの新規発言のみ。モジュールは不要。14.365 / PF2e 8.3.0の実FVTTで音声再生まで確認済み。他の版・システムは未確認 |
| Udonarium with Fly | 公開版1.11.2e（Udonarium 1.17.4）で取得を確認。Angularの開発用APIを使わず、元発言ID・`characterIdentifier`と新着通知から取得。DM・秘密・システム・操作ログ・プレイヤー発言・接続前の履歴を除外。対象チャットを一覧から選択。自動判別できない設置先は「取得方式」でFlyを選ぶ |
| 通常版ユドナリウム | 実験実装。`ng.getComponent`から元発言ID・公開範囲・話者種別が得られる場合だけ取得。通常の本番ビルドでは利用できない可能性が高く、取得不可時は理由を表示して停止 |
| ローカルAxe改の開発ビルド | 公開タブでプレイヤー発言を除外し、キャラID付き発言を取得する単独ブラウザ試験に成功。公開ビルドと複数参加者は未検証 |
| ココフォリア | 未実装の取得部分を明示して停止。元発言ID・新着判定・秘密/グループの除外を実部屋で調べてから有効化する |

通常版ユドナリウム・ココフォリアは実部屋での発言確認がまだです。FVTTの他の版・システム、公開版Axe、Safari/Firefox拡張も未確認です。

Flyは選択したタブのモデルを取得するために、`Map.prototype.get`を最長3秒だけ観測し、取得成功・失敗・中止のいずれでも元へ戻します。対象タブの`onChildAdded`に新着受信を追加し、停止時に元へ戻します。別タブの本文やオブジェクト一覧は取得しません。Flyの内部形式が変わった場合は、公開範囲を推測せず取得を停止します。公開版の単独ブラウザで公開・DM・秘密・操作ログ・同文の別発言と同名の別キャラを検証し、拡張からBridgeへの送信は独立した契約fixtureで検証しています。複数参加者の実卓とFly経由の実音声生成は未検証です。

## 操作の意味

- **読み上げ停止**: 再生中・保留中の音声を止め、遅れて完成した生成結果も破棄します。停止中もキャラ検出と声の設定はできます。
- **セッション終了**: 読み上げを停止し、参加URL・参加cookie・Collector接続を失効させます。
- **試聴**: Playerの未保存の設定を操作した本人だけに再生します。
- **参照音声に登録**: 直前の試聴音声を、IDを付けてIrodoriの参照音声（`POST /v1/audio/voices`）に登録します。登録できるのはBridgeが生成した試聴音声だけで、保持は10分です。新規登録のみで、既存IDの上書き・削除はできません。
- **Playerにセリフの本文を表示する**（管理画面の詳細設定）: 読み上げたセリフの本文をPlayerのログに表示します。既定はオンです。オフにすると、次のセリフからログには話者名だけを表示します。この設定は`data/bridge.sqlite`に保存されるため、既存の環境では初期値を変えても反映されません。管理画面で切り替えてください。
- **もう一度再生**（Playerのログ）: そのセリフを、押した本人のページでだけもう一度再生します。ほかの参加者には流れません。再生中の音声には割り込まず、その後に再生します。ミュート中のキャラも再生できます。音声の保存期間（10分）を過ぎたセリフと、読み上げ停止・セッション終了より前のセリフは再生できません。
- **声の編集**: その声を使用する全キャラに反映します。対象キャラ名を編集画面に表示します。通常の声変更は次の発言から適用します。
- **キャラの削除**（Playerの「キャラの声」）: 確認後、そのキャラの登録と声の割り当てを削除し、再生中・生成待ちの音声を取り消します。共通の声設定と上流サーバーの参照音声は残します。同じキャラが再びVTTで公開発言すると、声が未設定の状態で再登録されます。
- **設定を初期値に戻す**: 確認後、キャラ・声・紐付けをconfigの初期値へ戻し、停止状態にします。認証情報・接続先・入力元は残します。
- **上流の処理終了を確認して復帰**: タイムアウト時だけ表示します。失敗した発言の自動再送はしません。

Playerは通知の順に1件ずつ取得・デコード・再生します。先読みは行わないためPCMの保持は1件です。音量・キャラミュート・「最新へ戻る」があります。複数タブはBroadcastChannelで音声の有効なタブを切り替えます。初回参加・再読込時には、既に生成待ちの発言も含めて過去の音声を流しません。再読込時は、直近10分のセリフをログに復元します（自動再生はしません）。セリフの本文はメモリにだけ置き、`data/bridge.sqlite`には保存しません。10秒以内の同じページの再接続だけ通知を補完します。異なる端末間の同時再生は保証しません。

## 永続化・上限

`data/bridge.sqlite`に設定・キャラ・声・紐付け・入力元・認証情報・発言台帳を保存します。保存はトランザクションで処理し、編集対象の値を比較して競合を検出します。版番号は使用しません。別のキャラの編集だけでは保存を拒否しません。

`config.json`は初回登録とリセットの初期値です。通常の再起動ではDBの設定を使います。WAVは`data/audio/`の期限付き一時ファイルです。新しい発言は都度生成し、同じ発言IDの重複受信は再生成しません。本文はメモリだけに置き、台帳にはHMACを保存します。再起動時は停止状態になり、未完了の発言は再生成しません。

入力は500コードポイント・HTTP本文16KiBまで、未完了生成30件まで、生成は一つずつ、待機期限180秒・生成タイムアウト120秒です。入力流量は毎秒10件・バースト30件。WAVは25MiB/120秒まで、音声保管512MiB/10分、再生開始期限120秒、台帳24時間/10万件。保護中の音声は容量のために削除せず受付を抑制します。受付では最大WAVサイズで予約を見積もるので、30件より前に容量制限になる場合があります。試聴応答の保持は別途128MiBまでです。

招待は1時間、参加cookieは12時間またはセッション終了まで。「参加URLをコピー」は有効なURLを再利用します。詳細設定の「参加URLを再発行」は以前の招待リンクを無効化します。参加済み端末も失効させる場合は「セッション終了」です。管理操作のIdempotency-Key/commandIdはプロセス内で10分保持します。発言の重複排除はSQLiteで再起動を越えて保持します。

環境変数:

| 変数 | 既定値 | 用途 |
| --- | --- | --- |
| `TTS_BRIDGE_PORT` | `8090` | 待受ポート |
| `TTS_BRIDGE_HOST` | `127.0.0.1` | LAN待受時は明示変更 |
| `TTS_LOCAL_ORIGIN` | `http://127.0.0.1:ポート` | 管理画面の正規オリジン |
| `TTS_PUBLIC_ORIGIN` | なし | 外部の参加URL・WS Origin・Host許可（HTTP/HTTPS、末尾スラッシュなし） |
| `TTS_CONFIG_FILE` | `tts-bridge/config.json` | 初期値ファイル |
| `TTS_DATA_DIR` | `tts-bridge/data` | 永続データの格納先 |

Irodoriのモデルや推論バックエンドはBridgeから変更しません。

## 検証

```sh
npm test
npx playwright install chromium
npm run test:browser
# 起動中Irodoriを使う実生成とPlayerへの配信試験
TTS_REAL_E2E=1 npm run test:browser
# Fly公開サイトのモデルで新着・公開範囲を検証（独立したテスト用ブラウザ）
TTS_FLY_E2E=1 npx playwright test e2e/fly-production.spec.mjs
# 2声設定と登録参照voiceでWAV生成、verification/に記録
node tools/verify-real.mjs
```

ブラウザ試験は実Chromium上の独立した3コンテキストを使います。3台の物理端末や実VTTでの試験の代わりにはしません。

## 既存Axe用bridge

既存の`server.mjs`・`synthesis.mjs`・`delivery.mjs`とテストを維持しています。

```sh
TTS_BRIDGE_TOKEN=16文字以上の既存用トークン npm run start:legacy
```

従来どおり`/api/tts/health`、`profiles`、`voices`、`synthesize`を利用できます。`TTS_UPSTREAM`、`TTS_PROFILES`、`TTS_BRIDGE_PORT`も従来どおりです。新しい共通サービスに旧APIをマウントする互換入力はまだ追加していません。両方起動する場合はポートを分けてください。汎用bridge自体はサーバー側で自動再生しません。
