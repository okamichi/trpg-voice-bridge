# TRPG Voice Bridge

Bridgeの動きと設定の詳しい仕様です。Node.js **22.13以上** が必要で、`main.mjs` で起動します。依存はWebSocketの `ws` だけで、設定・認証・発言台帳はNode組み込みのSQLiteに保存します。

- 構成と、音声担当者・参加者それぞれの操作：[セットアップガイド](../docs/setup-guide.md)
- ソースからの起動と、実行ファイルのビルド：[ソースからのビルドと起動](../docs/build.md)
- Discord Botの準備：[Discordでの利用方法](../docs/discord.md)
- 別のPCの参加者への公開：[Playerの公開](../docs/online.md)

Collectorは音声担当者用のChrome拡張で、コードは `collector/` にあります。GMでもPLの一人でも担当できます。ほかの参加者は入れる必要はありません。

Playerの「チャット」から、Collectorなしでキャラを作成・選択して直接発言できます。「キャラ・声設定」で声を選び、TTSと読み上げが利用可能なら音声も生成します。声未設定・TTS未接続でも本文は保存・共有されます。VTTの隣のサイドパネルで使う場合は[Chatter拡張](chatter/README.md)を読み込んでください。

## 起動

```sh
cd tts-bridge
npm ci
npm start
```

Discord Botを使う場合は、`npm start` の前に `npm --prefix discord ci` も実行します。起動したら、端末に表示される管理用リンクを開きます。管理用リンクは共有しないでください。

## キャラの検出

キャラは、接続した卓の公開発言から検出します。非公開のNPCの一覧は取得も配信もしません。同じ名前でもキャラIDが違えば別のキャラです。

FVTTのキャラはActor単位で検出するので、シーンを切り替えても同じキャラとして扱います。以前のバージョンはシーン上のコマごとに検出していたため、同じキャラがシーンの数だけ一覧に並んでいることがあります。不要なものはPlayerのキャラ一覧から削除してください。古い登録が残っていると、そのコマのあるシーンでは古い登録の声を使います。

## VTTごとの取得方法

| VTT                      | 取得方法と対象                                                                                                                                                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FVTT 12/13/14            | 拡張から `createChatMessage` を登録します。Actor付きの公開IC発言の新着だけを取得します。モジュールは要りません                                                                                                                                                |
| ユドナリウム with Fly    | Angularの開発用APIを使わず、元の発言ID・`characterIdentifier` と新着通知から取得します。DM・秘密・システム・操作ログ・プレイヤー発言・接続前の履歴は除きます。対象チャットは一覧から選びます。自動で判別できない設置先では、「取得方式」でFlyを選んでください |
| ユドナリウム（従来方式） | `ng.getComponent` から元の発言ID・公開範囲・話者の種別を得られるページでだけ取得します。得られない場合は、理由を表示して止めます                                                                                                                              |
| ココフォリア             | 公開タブの新着の発言だけを取得します。キャラは投稿者IDと発言者名の組で区別します                                                                                                                                                                              |

**ココフォリア**では、ルームのチャットを開いたまま接続してください。

- 対象チャットは、表示しているタブにかかわらず「メイン」が初期値です。「対象チャット」の一覧には公開タブだけを表示します。表示名で選び、内部ではタブIDを使います。
- `1D6` だけの発言は取得しません。`1D100 ダイスを振ったわ！` なら「ダイスを振ったわ！」だけを送ります。ダイスの結果は本文に足しません。ダイスとして処理されなかった普通のセリフの中の `1D6` はそのまま残します。
- 既存の履歴と編集済みの発言は読み上げません。日時が確定していない投稿は、確定したあとに一度だけ送ります。
- 同じ投稿者でも発言者名が違えば別のキャラ、同じ名前でも投稿者が違えば別のキャラです。名前を変えると、別の声設定になります。
- 内部の形式・部屋・ストアが変わった場合や、対象タブが非公開になった場合は、取得を止めます。

**Fly**では、選んだタブのモデルを得るために `Map.prototype.get` を最長3秒だけ観測し、成功・失敗・中止のどの場合も元に戻します。対象タブの `onChildAdded` に新着の受信を足し、停止すると元に戻します。ほかのタブの本文やオブジェクトの一覧は取得しません。Flyの内部形式が変わった場合は、公開範囲を推測せずに取得を止めます。

## 操作の意味

- **読み上げ停止**：再生中・保留中の音声を止め、遅れて完成した生成結果も捨てます。停止中もキャラの検出と声の設定はできます。
- **セッション終了**：読み上げを止め、参加URL・参加cookie・Collectorの接続を失効させます。
- **試聴**：Playerのまだ保存していない設定で、操作した本人にだけ再生します。
- **参照音声に登録**：直前の試聴音声に名前（ID）を付けて、TTSの参照音声（`POST /v1/audio/voices`）に登録します。登録できるのはBridgeが作った試聴音声だけで、保持は10分です。新規の登録だけで、既存のIDの上書きや削除はできません。
- **感情・演技の指定方法**（管理画面の「5 声と読み上げの調整」）：自由な文章で書いた発言の指示を、声の説明文（caption）の後ろに足す（既定）、前に足す、置き換える、の3つから選べます。置き換えは参照音声を使う声だけに効き、参照音声のない声では後ろに足します。指示のない発言では、元の声の説明を使います。単語・絵文字の指示は今までどおりです。設定は保存され、次のセリフと試聴から反映します。生成待ちのセリフと、保存済みの声の説明は変わりません。
- **複数の文を含むセリフ**：「。」「！」「？」と改行で文に分け、1文ずつ生成して順に再生します。最初の文ができた時点で再生を始めます。分けるのは1発言10文までで、それより後は最後の文にまとめます。カッコ（）の中では分けません。「（演技:…）」の指示はすべての文に付け、単語・絵文字の指示は書いた文の中だけで効きます。Playerのログと「もう一度再生」は1文ずつです。
- **文の分割しきい値**（管理画面の「5 声と読み上げの調整」）：絵文字と感情・演技のタグ（`[感情:怒り]`・`[演技:強い怒りをこめて]`・`（怒り）` など）を除いた本文が、この文字数を超えたときだけ、句点・感嘆符・疑問符・改行で分けます。既定は150文字で、1～500文字で設定できます。ちょうどこの文字数なら分けません。句読点と本文中の空白は数えます。普通のカッコの中のセリフも本文に含みます。区切りのない長文は分けません。次のセリフから反映します。
- **文と文の間**（管理画面の「5 声と読み上げの調整」）：長いセリフを分けたときに、文と文の間に入れる無音の長さです。既定は0.9秒で、0～3秒で設定できます。次のセリフから反映します。
- **チャットとセリフの本文を共有する**（管理画面の「5 声と読み上げの調整」）：既定はオンです。オフにするとチャットの送信・履歴取得を停止し、Playerの表示済みログを消します。Collectorの音声生成は継続します。本文の保存は継続するため、オンに戻すと保持範囲内の履歴を表示できます。この設定は `bridge.sqlite` に保存されます。
- **卓のチャット履歴を消去**：確認のあと卓全体の本文を消去し、接続中Playerのログも消します。音声生成・配信の停止とは別の操作です。同じ発言の再送で本文は復活しません。
- **もう一度再生**（Playerのログ）：その発言の全音声パートを、押した本人のページでだけ順番に再生します。文と文の間の設定も適用します。ほかの参加者やDiscordには流れません。一部でも生成失敗・期限切れのパートがある場合は使えません。再生中の音声には割り込まず、その後に再生します。ミュート中のキャラも再生できます。音声の保存期間（10分）を過ぎたセリフと、読み上げ停止・セッション終了より前のセリフは再生できません。
- **声の編集**：その声を使っているすべてのキャラに反映します。対象のキャラ名を編集画面に表示します。普通の声の変更は、次の発言から使います。
- **キャラの削除**（Playerの「キャラの声」）：確認のあと、そのキャラの登録と声の割り当てを消し、再生中・生成待ちの音声を取り消します。共通の声の設定と、TTS側の参照音声は残します。同じキャラがまたVTTで公開発言すると、声が未設定の状態で登録し直されます。
- **設定を初期値に戻す**（管理画面の「初期化」）：確認のあと、キャラ・声・紐付けを `config.json` の初期値に戻し、読み上げを止めます。認証情報・接続先・入力元は残します。
- **Irodori側の処理終了を確認して復帰**：生成がタイムアウトしたときだけ表示します。失敗した発言を自動で送り直すことはしません。

Playerは、通知の順に1件ずつ取得・デコード・再生します。再生中に次の1件を取得・デコードしておくので、PCMを持つのは最大2件です。音量・キャラごとのミュート・「最新へ戻る」があります。複数のタブで開いた場合は、BroadcastChannelで音声を鳴らすタブを切り替えます。初めて参加したときと再読み込みしたときは、生成待ちの発言も含めて、それまでの音声を流しません。Playerは保存済みチャットの最新100件までを表示します（上にスクロールしている間は表示位置を保ちます）。音声は自動では再生しません。チャットの追加・音声状態更新・削除は更新番号で同期し、差分保持範囲外の場合は最新100件を取得し直します。同じページが10秒以内に再接続した場合だけ、その間の音声通知を補います。別々の端末で同時に再生されることは保証しません。

## 保存と上限

保存先（既定は `tts-bridge/data/`、`TTS_DATA_DIR` で変更）の `bridge.sqlite` に、設定・キャラ・声・紐付け・入力元・認証情報・発言台帳を保存します。保存はトランザクションで行い、編集する値を比べて競合を見つけます。版番号は使いません。別のキャラを編集しただけでは保存を断りません。

`config.json` は、初めての登録とリセットで使う初期値です。普段の再起動ではDBの設定を使います。WAVは、保存先の `audio/` に置く期限付きの一時ファイルです。新しい発言はその都度生成し、同じ発言IDを重ねて受け取っても生成し直しません。通常発言の本文はSQLiteのチャット履歴に直近7日・最大10,000件まで保存します。再起動すると読み上げは停止状態になり、終わっていない発言は生成し直しません。声登録・削除コマンドは通常チャットに保存しません。

入力は500コードポイント・HTTPの本文16KiBまで、未完了の生成は30件まで、生成は一つずつ、待機の期限は180秒、生成のタイムアウトは120秒です。入力の流量は毎秒10件・バースト30件です。WAVは25MiB・120秒まで、音声の保管は512MiB・10分、再生開始の期限は120秒、台帳は24時間・10万件です。保護中の音声は容量のために消さず、受付を抑えます。受付ではWAVの最大サイズで予約を見積もるので、30件より前に容量の上限に達することがあります。試聴の応答は、別に128MiBまで持ちます。

音声のキュー・容量・TTSの不調で生成できなくても、チャット本文の受付は成功し、音声状態を失敗として保存します。チャット受付台帳は音声用の24時間の台帳と別で、最低7日かつ受付セッションが有効な間保持します（上限10万件）。履歴消去後も重複判定は残します。更新履歴は7日・最大50,000件で、範囲外の差分要求には再同期が必要なことを返します。

## 参加者用チャットAPI

既存の招待を `POST /api/v1/join` で交換した参加Cookieを使います。Collectorの接続・入力元登録は不要です。`GET /api/v1/rooms/:roomId/state` から現在のセッションID、参加資格に紐付く `participantId`、`chat` の共有状態・履歴世代を取得できます。`participantId` は認証トークンではありません。再参加で変化した場合、前の資格で送信結果が不明な発言は自動再送せず下書きとして扱います。

| API | 入力と動作 |
| --- | --- |
| `POST /api/v1/rooms/:roomId/characters` | `{displayName}` と `Idempotency-Key` ヘッダー。VTTへの紐付けなし・声未設定のキャラを作成 |
| `POST /api/v1/rooms/:roomId/messages` | `{characterId, text, clientMessageId, sessionId}`。成功は201、同一内容の再送は200、同じIDの内容変更は409 |
| `GET /api/v1/rooms/:roomId/messages` | `limit`（1～100、既定100）、`before` または `after`（発言番号）。本文と音声状態を取得 |
| `GET /api/v1/rooms/:roomId/message-changes` | `generation` と `since`（更新番号）、任意の `limit`。`hasMore` の間は `nextSince` で追従。`resetRequired` の場合は履歴を再取得 |
| `GET /downloads/chatter.zip` | Chatter拡張のZIP。参加資格不要、許可されたHostのみ |
| `POST /api/v1/leave` | 現在の参加CookieまたはChatterトークンを失効し、同じ資格のWebSocketを切断 |
| `DELETE /api/v1/admin/chat-history` | 管理者専用。履歴を消去して世代を更新 |

送信ごとにUUIDを作り、通信再試行では同じ `clientMessageId` を使います。受付結果の `messageId` と発言番号は不変です。削除済み発言の再送では `deleted: true` を返し、復活・再生成しません。WebSocketでは `chat.message.created` / `chat.message.updated` / `chat.message.deleted` と `chat.reset` を通知します。履歴と変更通知は表示更新のためのもので、過去音声を再生キューへ投入しないでください。Chatterは `POST /api/v1/chatter/join` で招待をBearerトークンへ交換します。HTTP・音声取得は認証ヘッダー、WebSocketは最初の `hello` でトークンを送ります。詳細は[Chatterの認証と権限](chatter/README.md#認証と権限)を参照してください。

招待は1時間、参加cookieは12時間かセッション終了まで有効です。「参加URLをコピー」は有効なURLを使い回します。「4 卓の開始」の「参加URLを再発行」は、以前の招待リンクを無効にします。参加済みの端末も失効させるには「セッション終了」を使います。管理操作のIdempotency-Key・commandIdは、プロセスの中で10分持ちます。発言の重複排除はSQLiteで行い、再起動しても続きます。

## 環境変数

| 変数                | 既定値                    | 用途                                                                                        |
| ------------------- | ------------------------- | ------------------------------------------------------------------------------------------- |
| `TTS_BRIDGE_PORT`   | `8090`                    | 待ち受けポート                                                                              |
| `TTS_BRIDGE_HOST`   | `127.0.0.1`               | 待ち受けアドレス。別のPCから接続させるときは `0.0.0.0`（[Playerの公開](../docs/online.md)） |
| `TTS_LOCAL_ORIGIN`  | `http://127.0.0.1:ポート` | 管理画面の正規のOrigin                                                                      |
| `TTS_PUBLIC_ORIGIN` | なし                      | 参加URL・WebSocketのOrigin・Hostとして外から許可するもの（HTTPかHTTPS、末尾の `/` なし）    |
| `TTS_CONFIG_FILE`   | `tts-bridge/config.json`  | 初期値のファイル                                                                            |
| `TTS_DATA_DIR`      | `tts-bridge/data`         | 保存先                                                                                      |

外部TTSのモデルや推論のバックエンドは、Bridgeからは変えません。
