# TRPG Voice Bridge

Node.js **22.13以上**。既存Axe用のコードを残し、汎用bridgeは`main.mjs`で起動します。依存はWebSocketの`ws`、永続台帳はNode組込みSQLiteです。

構成と音声担当者・参加者それぞれの操作は[セットアップガイド](../docs/setup-guide.md)を先に参照してください。Collectorは音声担当者用のブラウザ拡張です。GMでもPLの一人でも担当できます。コードは`collector/`に含まれ、ほかの参加者にはインストール不要です。

## 起動

```sh
cd tts-bridge
npm ci
npm start
```

1. `http://127.0.0.1:8090/admin/`を開きます。`localhost`ではなく、このURLを使用します。
2. `data/credentials.json`の`admin`を管理トークン欄へ入力します。自動生成ファイルは所有者だけが読める権限です。`hmac`は内部用です。
3. Irodori接続を診断し、声の「編集・試聴」から参照voice・caption・seed・速度・ステップを調整します。既存`profiles.json`の4キャラは初回だけ取り込みます。以後の正本は`data/config.json`です。
4. 入力元にツール、任意の入力元ID、部屋IDを登録します。FVTTでは部屋IDに`game.world.id`を指定します。
5. Chrome/Chromiumの拡張機能画面でデベロッパーモードを有効にし、「パッケージ化されていない拡張機能を読み込む」から`collector/`を選びます。
6. VTTのタブを開き、拡張のアイコンを押します。Bridge URL、`credentials.json`の`collector`、管理画面と同じ入力元・部屋を入力して接続します。FVTTの対象チャットは`main`です。
7. 管理画面で読み上げを開始します。未登録話者の最初の発言は読みません。「未登録の発言者」は管理画面を表示中、5秒ごとに自動更新されます。話者を登録または既存キャラへ紐付けると、次の新規発言から指定の声になります。
8. 「参加URLを発行」を押し、参加者がそのURLで「音声を有効にする」を押すと、以後の新しい発言が流れます。ローカルURLは同じPC内の確認用です。オンライン配信には[HTTPSの設定](../docs/online.md)が必要です。

キャラごとに任意の外部ID・名前bindingを管理画面で追加できます。Token上書きにはScene IDとToken IDの両方を指定します。名前だけの紐付けには同名キャラがいないことの確認が必要で、改名後の再登録も必要です。

**VTT取得の現在地:**

| ツール | 実装・制約 |
| --- | --- |
| FVTT 12/13/14 | 拡張から`createChatMessage`を登録。公開IC・Actor付きの新規発言のみ。モジュールは不要。14.365 / PF2e 8.3.0の実FVTTで音声再生まで確認済み。他の版・システムは未確認 |
| 通常版ユドナリウム | 実験実装。`ng.getComponent`から元発言ID・公開範囲・話者種別が得られる場合だけ取得。通常の本番ビルドでは利用できない可能性が高く、取得不可時は理由を表示して停止 |
| ローカルAxe改の開発ビルド | 公開タブでプレイヤー発言を除外し、キャラID付き発言を取得する単独ブラウザ試験に成功。公開ビルドと複数参加者は未検証 |
| ココフォリア | 未実装の取得部分を明示して停止。元発言ID・新着判定・秘密/グループの除外を実部屋で調べてから有効化する |

通常版ユドナリウム・ココフォリアは実部屋での発言確認がまだです。FVTTの他の版・システム、公開版Axe、Safari/Firefox拡張も未確認です。

## 操作の意味

- **読み上げ停止**: 新しい入力を無視します。受理済み音声は継続します。
- **全停止**: 現在音声と保留音声を止め、遅れて完成した生成結果も破棄します。再開には「読み上げ開始」。
- **セッション終了**: 全停止し、招待・参加cookie・Collector接続を失効させます。
- **キャラ無効化/削除**: そのキャラの未開始音声を破棄します。再生中の音声は最後まで継続します。
- **試聴**: 未保存の設定を管理画面だけで再生します。参加者へは配信しません。
- **もう一度再生**: 診断欄の直近のready音声を、生成済みファイルから新しい再生注文として配信します。
- **上流の処理終了を確認して復帰**: タイムアウトで停止した生成キューを再開します。失敗した発言のTTS要求を自動再送する操作ではありません。

Playerは通知の順に1件ずつ取得・デコード・再生します。先読みは行わないためPCMの保持は1件です。音量・キャラミュート・「最新へ戻る」があります。複数タブはBroadcastChannelで音声の有効なタブを切り替えます。初回参加・再読込時には、既に生成待ちの発言も含めて過去の音声を流しません。10秒以内の同じページの再接続だけ通知を補完します。異なる端末間の同時再生は保証しません。

## 永続化・上限

`data/`に設定、10世代の設定バックアップ、認証情報、SQLite台帳、期限付き音声を保存します。設定更新にはrevisionが必要です。入力本文はメモリだけに置き、台帳にはHMACを保存します。再起動で未完了注文を再生成しません。新しいセッションは停止状態で起動します。

入力は500コードポイント・HTTP本文16KiBまで、未完了生成30件まで、生成は一つずつ、待機期限180秒・生成タイムアウト120秒です。入力流量は毎秒10件・バースト30件。WAVは25MiB/120秒まで、音声保管512MiB/10分、再生開始期限120秒、台帳24時間/10万件。保護中の音声は容量のために削除せず受付を抑制します。受付では最大WAVサイズで予約を見積もるので、30件より前に容量制限になる場合があります。試聴応答の保持は別途128MiBまでです。

招待は1時間、参加cookieは12時間またはセッション終了まで。招待再発行は以前の招待リンクを無効化します。参加済み端末も失効させる場合は「セッション終了」です。管理操作のIdempotency-Key/commandIdはプロセス内で10分保持します。発言の重複排除はSQLiteで再起動を越えて保持します。

環境変数:

| 変数 | 既定値 | 用途 |
| --- | --- | --- |
| `TTS_BRIDGE_PORT` | `8090` | 待受ポート |
| `TTS_BRIDGE_HOST` | `127.0.0.1` | LAN待受時は明示変更 |
| `TTS_LOCAL_ORIGIN` | `http://127.0.0.1:ポート` | 管理画面の正規オリジン |
| `TTS_PUBLIC_ORIGIN` | なし | HTTPSの参加URL・WS Origin・Host許可 |
| `TTS_DATA_DIR` | `tts-bridge/data` | 永続データの格納先 |

Irodoriのモデルや推論バックエンドはbridgeから変更しません。今回の環境では`.env`の`IRODORI_CHECKPOINT`がLargeを指定しています。healthの`model.hf_checkpoint`はフォールバック設定であり、ロード済みの`runtime.checkpoint`を優先して確認してください。

## 検証

```sh
npm test
npx playwright install chromium
npm run test:browser
# 起動中Irodoriを使う実生成とPlayerへの配信試験
TTS_REAL_E2E=1 npm run test:browser
# 2声設定と登録参照voiceでWAV生成、verification/に記録
node tools/verify-real.mjs
```

ブラウザ試験は実Chromium上の独立した3コンテキストを使います。3台の物理端末や実VTTでの試験の代わりにはしません。

## 既存Axe用bridge

既存の`server.mjs`・`synthesis.mjs`・`delivery.mjs`とテストを維持しています。

```sh
TTS_BRIDGE_TOKEN=16文字以上の既存用トークン npm run start:legacy
```

従来どおり`/api/tts/health`、`profiles`、`voices`、`synthesize`を利用できます。`TTS_UPSTREAM`、`TTS_PROFILES`、`TTS_BRIDGE_PORT`も従来どおりです。新しい共通サービスに旧APIをマウントする互換入力はまだ追加していません。両方起動する場合はポートを分けてください。汎用bridge自体はサーバー側で自動再生しません。
